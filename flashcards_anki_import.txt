<b>Bubble Sort</b> — Explain how it works (steps, ~4 bullets), code it in C, and state time &amp; space complexity (best / avg / worst, space).	<b>Principle (steps):</b><br><ol><br><li>Walk through the array from left to right.</li><br><li>For every adjacent pair, if the left element is greater than the right, swap them.</li><br><li>After one full pass, the largest unsorted element has 'bubbled up' to the end → it is now in its final position.</li><br><li>Repeat for the remaining unsorted prefix. After <i>i</i> passes the last <i>i</i> elements are sorted.</li><br></ol><br><b>C code:</b><br><pre><code>void bubble_sort(int a[], int n) {<br>    // i counts how many passes we have done<br>    // after pass i the last i elements are already in place<br>    for (int i = 0; i &lt; n - 1; i++) {<br>        // j stops at n-1-i because the last i elements are already sorted<br>        for (int j = 0; j &lt; n - 1 - i; j++) {<br>            if (a[j] &gt; a[j+1]) {<br>                int tmp = a[j];<br>                a[j]    = a[j+1];<br>                a[j+1]  = tmp;<br>            }<br>        }<br>    }<br>}</code></pre><br><b>Complexity:</b><br><ul><br><li>Time — Best / Average / Worst: <b>O(n²)</b>.</li><br><li>Space: <b>O(1)</b>, in-place.</li><br></ul>	Info2::Sorting
<b>Selection Sort</b> — Explain how it works (steps, ~4 bullets), code it in C, and state time &amp; space complexity (best / avg / worst, space).	<b>Principle (steps):</b><br><ol><br><li>Split the array conceptually into a sorted prefix (initially empty) and an unsorted suffix.</li><br><li>Scan the unsorted suffix to find the minimum element.</li><br><li>Swap that minimum with the first element of the unsorted suffix → the sorted prefix grows by one.</li><br><li>Repeat until the unsorted suffix is empty. Exactly <i>n − 1</i> swaps in total.</li><br></ol><br><b>C code:</b><br><pre><code>void selection_sort(int a[], int n) {<br>    // i = boundary; the sorted prefix is a[0..i-1]<br>    for (int i = 0; i &lt; n - 1; i++) {<br>        // min_idx = index of the smallest element found so far in the unsorted part<br>        int min_idx = i;<br>        // scan the unsorted suffix [i+1, n)<br>        for (int j = i + 1; j &lt; n; j++) {<br>            if (a[j] &lt; a[min_idx]) {<br>                min_idx = j;<br>            }<br>        }<br>        // put the minimum at position i (skip swap if it's already there)<br>        if (min_idx != i) {<br>            int tmp     = a[i];<br>            a[i]        = a[min_idx];<br>            a[min_idx]  = tmp;<br>        }<br>    }<br>}</code></pre><br><b>Complexity:</b><br><ul><br><li>Time — Best / Average / Worst: <b>O(n²)</b> (always scans the full suffix, no early exit).</li><br><li>Space: <b>O(1)</b>, in-place.</li><br><li>Nice property: only <b>O(n)</b> swaps total → good when writes are expensive.</li><br></ul>	Info2::Sorting
<b>Insertion Sort</b> — Explain how it works (steps, ~5 bullets), code it in C, and state time &amp; space complexity (best / avg / worst, space).	<b>Principle (steps):</b><br><ol><br><li>Treat the first element as a sorted sub-array of length 1.</li><br><li>Take the next element (the <i>key</i>) from the unsorted part.</li><br><li>Shift every element of the sorted part that is greater than the key one position to the right.</li><br><li>Insert the key into the gap so the sorted part is sorted again.</li><br><li>Repeat for every remaining element. Sorted region grows by 1 each iteration.</li><br></ol><br><b>C code:</b><br><pre><code>void insertion_sort(int a[], int n) {<br>    // i = first index of the unsorted part; sorted part is a[0..i-1]<br>    for (int i = 1; i &lt; n; i++) {<br>        // key = element we are inserting into the sorted prefix<br>        int key = a[i];<br>        // j walks left through the sorted prefix<br>        int j   = i - 1;<br>        // shift every element greater than key one position to the right<br>        while (j &gt;= 0 &amp;&amp; a[j] &gt; key) {<br>            a[j+1] = a[j];<br>            j--;<br>        }<br>        // j+1 is the correct slot for key (the gap left by the shifting)<br>        a[j+1] = key;<br>    }<br>}</code></pre><br><b>Complexity:</b><br><ul><br><li>Time — Best: <b>O(n)</b> (already sorted, inner while exits immediately). Average / Worst: <b>O(n²)</b>.</li><br><li>Space: <b>O(1)</b>, in-place.</li><br><li>Excellent for <b>small</b> or <b>nearly-sorted</b> arrays.</li><br></ul>	Info2::Sorting
<b>Quick Sort</b> — Explain how it works (steps, ~4 bullets), code it in C (Hoare partition), and state time &amp; space complexity (best / avg / worst, space).	<b>Principle (steps):</b><br><ol><br><li>Base case: a sub-array of length ≤ 1 is sorted → return.</li><br><li>Pick a <i>pivot</i> (we use <code>a[lo]</code> here; see the pivot-choice card for better options).</li><br><li><b>Partition (Hoare):</b> two pointers walk towards each other from both ends, swapping out-of-place elements, until they cross. Result: every element left of the split is ≤ pivot, every element right of the split is ≥ pivot.</li><br><li>Recursively quicksort both halves. With Hoare you recurse on <code>[lo, p]</code> and <code>[p+1, hi]</code> (note: <code>p</code>, not <code>p−1</code>, because the pivot is not guaranteed to land at index <code>p</code>).</li><br></ol><br><b>C code (Hoare partition):</b><br><pre><code>static void swap(int *x, int *y) {<br>    int tmp = *x; *x = *y; *y = tmp;<br>}<br><br>// Hoare partition: returns an index p such that<br>//   every element in a[lo..p]   is &lt;= pivot,<br>//   every element in a[p+1..hi] is &gt;= pivot.<br>// (The pivot itself can end up anywhere on the left side.)<br>int hoare_partition(int a[], int lo, int hi) {<br>    // pivot value (any choice works; we take the first element)<br>    int pivot = a[lo];<br>    // i = left pointer, starts just OUTSIDE the range; will move right<br>    int i = lo - 1;<br>    // j = right pointer, starts just OUTSIDE the range; will move left<br>    int j = hi + 1;<br>    while (1) {<br>        // advance i until we find an element NOT smaller than pivot<br>        do { i++; } while (a[i] &lt; pivot);<br>        // advance j until we find an element NOT greater than pivot<br>        do { j--; } while (a[j] &gt; pivot);<br>        // if the pointers crossed, the partition is complete<br>        if (i &gt;= j) return j;<br>        // otherwise a[i] and a[j] are on the wrong sides → swap them<br>        swap(&amp;a[i], &amp;a[j]);<br>    }<br>}<br><br>void quick_sort(int a[], int lo, int hi) {<br>    if (lo &lt; hi) {<br>        int p = hoare_partition(a, lo, hi);<br>        // with Hoare we use p (NOT p-1) for the left recursive call<br>        quick_sort(a, lo, p);<br>        quick_sort(a, p + 1, hi);<br>    }<br>}</code></pre><br><b>Complexity:</b><br><ul><br><li>Time — Best / Average: <b>O(n log n)</b>. Worst: <b>O(n²)</b> (bad pivot every time, e.g. always picking the smallest / largest element).</li><br><li>Space: <b>O(log n)</b> recursion stack on average, <b>O(n)</b> in the worst case. In-place (no extra array).</li><br><li>In practice the fastest comparison sort due to good cache behavior and small constants.</li><br></ul>	Info2::Sorting
<b>Quick Sort</b> — What is the best choice for a good pivot, and why? (3 practical choices + why pivot choice matters)	<b>Ideal pivot:</b> the <i>median</i> of the sub-array → both partitions have size ≈ n/2 → recursion depth ≈ log n → total <b>O(n log n)</b>.<br>But finding the true median costs an extra O(n) per call → too expensive in practice.<br><br><b>Three practical pivot strategies:</b><br><ol><br><li><b>Random pivot</b> — pick a uniformly random index in <code>[lo, hi]</code>. Defeats adversarial inputs (sorted / reverse-sorted arrays). Expected <b>O(n log n)</b>, worst case still possible but extremely unlikely.</li><br><li><b>Median-of-three</b> — take the median of <code>a[lo]</code>, <code>a[mid]</code>, <code>a[hi]</code>. Cheap (3 comparisons), usually much closer to the true median than any single element. This is what most real-world implementations use.</li><br><li><b>Middle element</b> <code>a[(lo+hi)/2]</code> — simple; avoids the O(n²) worst case on already-sorted input (the classic trap when using the first or last element).</li><br></ol><br><b>Why does pivot choice matter so much?</b><br><ul><br><li>A pivot near the median splits the array roughly in half → recursion depth ≈ <b>log n</b> → <b>O(n log n)</b> total work.</li><br><li>A pivot at the extreme (always min or max) splits into sizes 0 and n−1 → recursion depth ≈ <b>n</b> → <b>O(n²)</b> total.</li><br><li>So the pivot choice is exactly what separates the <i>average</i> case from the <i>worst</i> case in quicksort.</li><br></ul>	Info2::Sorting
<b>Heap Sort</b> — Explain what a <i>heap</i> is, how heap sort works (steps, ~5 bullets), code <code>heapify</code> and <code>heap_sort</code> in C, and state time &amp; space complexity (best / avg / worst, space).	<b>What is a heap?</b><br><br>A <b>heap</b> is a <i>complete binary tree</i> (filled level-by-level, left-to-right) stored implicitly in an array. In a <b>max-heap</b>, every parent ≥ both its children (min-heap: parent ≤ children). For an element at index <code>i</code> (0-indexed):<br><ul><br><li>Parent: <code>(i − 1) / 2</code></li><br><li>Left child: <code>2·i + 1</code></li><br><li>Right child: <code>2·i + 2</code></li><br></ul><br><b>Heap sort — steps:</b><br><ol><br><li><b>Build max-heap:</b> call <code>heapify</code> on every non-leaf node from index <code>n/2 − 1</code> down to <code>0</code>. Costs O(n).</li><br><li>The maximum element is now at index 0 (the root).</li><br><li>Swap <code>a[0]</code> with <code>a[i]</code> (the last element of the active heap) → max is placed in its final position.</li><br><li>Shrink the heap by 1 and call <code>heapify(a, i, 0)</code> to restore the max-heap property.</li><br><li>Repeat until the heap has 1 element. The array is now sorted ascending.</li><br></ol><br><b>C code:</b><br><pre><code>// Restore the max-heap property at node i,<br>// assuming the subtrees rooted at 2i+1 and 2i+2 are already valid heaps.<br>// n = size of the currently active heap.<br>void heapify(int a[], int n, int i) {<br>    // largest = index of the largest of {i, left child, right child}<br>    int largest = i;<br>    int l = 2*i + 1;   // left child<br>    int r = 2*i + 2;   // right child<br>    // compare with left child (only if it exists, i.e. l &lt; n)<br>    if (l &lt; n &amp;&amp; a[l] &gt; a[largest]) largest = l;<br>    // compare with right child (only if it exists)<br>    if (r &lt; n &amp;&amp; a[r] &gt; a[largest]) largest = r;<br>    // if a child was larger, swap and recurse down into that child<br>    if (largest != i) {<br>        int tmp = a[i]; a[i] = a[largest]; a[largest] = tmp;<br>        heapify(a, n, largest);<br>    }<br>}<br><br>void heap_sort(int a[], int n) {<br>    // ----- BUILD MAX-HEAP -----<br>    // Leaves (indices n/2 .. n-1) are trivially valid heaps on their own,<br>    // so we only need to heapify INTERNAL nodes.<br>    // We go bottom-up (last internal node → root) so that when heapify runs,<br>    // the children of i are already valid heaps. This is what makes<br>    // build-heap cost O(n) instead of O(n log n).<br>    for (int i = n/2 - 1; i &gt;= 0; i--) {<br>        heapify(a, n, i);<br>    }<br>    // ----- SORT -----<br>    // Repeatedly move the current max (root) to the end,<br>    // then restore the heap on the shrunken range [0, i).<br>    for (int i = n - 1; i &gt; 0; i--) {<br>        // move max (root) to position i (its final spot)<br>        int tmp = a[0]; a[0] = a[i]; a[i] = tmp;<br>        // active heap is now of size i; restore property at root<br>        heapify(a, i, 0);<br>    }<br>}</code></pre><br><b>Complexity:</b><br><ul><br><li>Time — Best / Average / Worst: <b>O(n log n)</b>. Build-heap is O(n), then n − 1 extractions cost O(log n) each.</li><br><li>Space: <b>O(1)</b> in-place (iterative <code>heapify</code>) or O(log n) recursion stack as written above.</li><br></ul>	Info2::Sorting
<b>Merge Sort</b> — Explain the <i>divide-and-conquer</i> principle (3 phases) and how merge sort applies it (steps, ~4 bullets), code it in C, and state time &amp; space complexity (best / avg / worst, space).	<b>Divide &amp; Conquer (3 phases):</b><br><ol><br><li><b>Divide</b> the problem into smaller sub-problems of the same type.</li><br><li><b>Conquer</b> each sub-problem recursively (base case: trivial size).</li><br><li><b>Combine</b> the sub-solutions into a solution of the original problem.</li><br></ol><br><b>Merge sort — steps:</b><br><ol><br><li>Base case: a sub-array of length ≤ 1 is already sorted → return.</li><br><li><b>Divide:</b> split the array at the middle index into two halves.</li><br><li><b>Conquer:</b> recursively merge-sort both halves.</li><br><li><b>Combine (merge):</b> walk two pointers through the two sorted halves and write the smaller current element into the output → produces one sorted array.</li><br></ol><br><b>C code:</b><br><pre><code>// Merge two already-sorted halves a[lo..mid] and a[mid+1..hi]<br>// into one sorted run stored back in a[lo..hi].<br>void merge(int a[], int lo, int mid, int hi) {<br>    // n1 = size of left half, n2 = size of right half<br>    int n1 = mid - lo + 1;<br>    int n2 = hi - mid;<br><br>    // create two temporary arrays and copy the two halves into them<br>    // (we need copies because we will overwrite a[lo..hi] while merging)<br>    int L[n1], R[n2];<br>    for (int i = 0; i &lt; n1; i++) L[i] = a[lo + i];<br>    for (int j = 0; j &lt; n2; j++) R[j] = a[mid + 1 + j];<br><br>    // i = read cursor in L, j = read cursor in R, k = write cursor in a<br>    int i = 0, j = 0, k = lo;<br><br>    // walk through BOTH halves at the same time<br>    while (i &lt; n1 &amp;&amp; j &lt; n2) {<br>        // pick whichever current element is smaller and copy it to a[k]<br>        if (L[i] &lt;= R[j]) a[k++] = L[i++];<br>        else              a[k++] = R[j++];<br>    }<br>    // at this point ONE of the two halves is fully consumed;<br>    // copy the leftover elements of the OTHER half (they are already sorted)<br>    while (i &lt; n1) a[k++] = L[i++];<br>    while (j &lt; n2) a[k++] = R[j++];<br>}<br><br>void merge_sort(int a[], int lo, int hi) {<br>    // base case: 0 or 1 elements → already sorted, nothing to do<br>    if (lo &lt; hi) {<br>        // DIVIDE: compute midpoint<br>        // (the form lo + (hi-lo)/2 avoids integer overflow vs. (lo+hi)/2)<br>        int mid = lo + (hi - lo) / 2;<br><br>        // CONQUER: recursively sort each half<br>        merge_sort(a, lo, mid);        // left half:  a[lo..mid]<br>        merge_sort(a, mid + 1, hi);    // right half: a[mid+1..hi]<br><br>        // COMBINE: merge the two sorted halves back together<br>        merge(a, lo, mid, hi);<br>    }<br>}</code></pre><br><b>Complexity:</b><br><ul><br><li>Time — Best / Average / Worst: <b>O(n log n)</b> (recurrence T(n) = 2·T(n/2) + Θ(n)).</li><br><li>Space: <b>O(n)</b> extra for the merge buffers + O(log n) recursion stack. <b>Not</b> in-place.</li><br></ul>	Info2::Sorting
<b>Dual-Pivot Quicksort</b> — In a dual-pivot quicksort implementation, an array <code>A[low...high]</code> is sorted based on two pivots <code>p1 = A[low]</code> and <code>p2 = A[high]</code>. The pivot <code>p1</code> must be less than <code>p2</code>, otherwise they have to be swapped. Here <code>low</code> is the left end of the array <code>A</code> and <code>high</code> is the right end of the array <code>A</code>.<br><br><br>The partitioning process is the core of the dual-pivot quicksort. We begin partitioning the array into three proper partitions I, II and III, where:<br><ul><br><li>Partition I: all elements are less than the left pivot <code>p1</code>.</li><br><li>Partition II: all elements are greater or equal to <code>p1</code> and less than the right pivot <code>p2</code>.</li><br><li>Partition III: all elements are greater than or equal to the right pivot <code>p2</code>.</li><br></ul><br>After partitioning, the two pivots are placed in their proper final positions and the process is repeated recursively on each of the three partitions.<br><br><br>Create a C program that implements dual-pivot quicksort to sort an array <code>A</code> of integers in increasing order. Your program should also print the array before and after sorting. For example, if the array is <code>[10, 7, 3, 15, 6, 2, 5, 1, 17, 8]</code>, the output should contain:<br><pre><code>Before: [ 10 7 3 15 6 2 5 1 17 8 ]<br>After:  [ 1 2 3 5 6 7 8 10 15 17 ]</code></pre>	<b>Quick explanation in words:</b><br><ul><br><li>Choose two pivots: the leftmost and the rightmost element.</li><br><li>If they are in the wrong order, swap them so <code>p1 &lt;= p2</code>.</li><br><li>Then scan the array once and split it into three regions: smaller than <code>p1</code>, between the pivots, and greater or equal to <code>p2</code>.</li><br><li>Finally, put both pivots into their final places and recursively sort the three remaining parts.</li><br></ul><br><b>C code:</b><br><pre><code>#include &lt;stdio.h&gt;<br><br>#define ARRAY_SIZE 10<br><br>void swap(int A[], int i, int j) {<br>    // swap the two elements at indices i and j<br>    int tmp = A[i];<br>    A[i] = A[j];<br>    A[j] = tmp;<br>}<br><br>void printArray(int a[], int size) {<br>    // print the array in the required format: [ 1 2 3 ]<br>    printf("[");<br>    for (int i = 0; i &lt; size; i++) {<br>        printf(" %d", a[i]);<br>    }<br>    printf(" ]\\n");<br>}<br><br>void partitioning(int A[], int low, int high, int *p1, int *p2) {<br>    // A[low] is the left pivot, A[high] is the right pivot<br>    // l = first free position in partition I  (< p1)<br>    // k = current scanning index<br>    // g = first position of partition III (>= p2) from the right<br>    int l = low + 1;<br>    int k = low + 1;<br>    int g = high;<br><br>    // scan the array once and move each element into its correct partition<br>    while (k &lt; g) {<br>        // belongs to partition I: move it to the left side<br>        if (A[k] &lt; A[low]) {<br>            swap(A, l, k);<br>            l++;<br>            k++;<br>        }<br>        // belongs to partition III: move it to the right side<br>        else if (A[k] &gt;= A[high]) {<br>            g--;<br>            swap(A, k, g);<br>            // do NOT increment k here:<br>            // the element swapped in from the right has not been inspected yet<br>        }<br>        // otherwise it belongs to partition II and stays in the middle<br>        else {<br>            k++;<br>        }<br><br>        // prints intermediate partitioning steps<br>        printArray(A, ARRAY_SIZE);<br>    }<br><br>    // place the pivots into their final positions<br>    swap(A, low, l - 1);<br>    swap(A, high, k);<br><br>    // return the pivot positions through pointers<br>    *p1 = l - 1;<br>    *p2 = k;<br>}<br><br>void quicksort(int A[], int low, int high) {<br>    // base case: empty part or single element => already sorted<br>    if (high - low &lt;= 0) {<br>        return;<br>    }<br><br>    // ensure the left pivot is not larger than the right pivot<br>    if (A[low] &gt; A[high]) {<br>        swap(A, low, high);<br>    }<br><br>    int p1, p2;<br><br>    // partition the current subarray around the two pivots<br>    partitioning(A, low, high, &p1, &p2);<br><br>    // recursively sort the three partitions<br>    quicksort(A, low, p1 - 1);<br>    quicksort(A, p1 + 1, p2 - 1);<br>    quicksort(A, p2 + 1, high);<br>}<br><br>int main() {<br>    int A[] = {10, 7, 3, 15, 6, 2, 5, 1, 17, 8};<br>    int n = 10;<br><br>    printf("Before: ");<br>    printArray(A, n);<br><br>    quicksort(A, 0, n - 1);<br><br>    printf("After:  ");<br>    printArray(A, n);<br><br>    return 0;<br>}</code></pre>	Info2::Sorting
<b>Time complexity</b> — Rank the 8 most common time complexity classes from smallest (fastest) to largest (slowest).	<b>Ranking (smallest → largest):</b><br><pre><code>O(1) &lt; O(log n) &lt; O(n) &lt; O(n log n) &lt; O(n²) &lt; O(n³) &lt; O(2ⁿ) &lt; O(n!)</code></pre><br><b>What each one is:</b><br><ul><br><li><b>O(1)</b> — constant: same time regardless of n (array access, hash lookup).</li><br><li><b>O(log n)</b> — logarithmic: each step halves the problem (binary search).</li><br><li><b>O(n)</b> — linear: one pass through the input.</li><br><li><b>O(n log n)</b> — linearithmic: good comparison sorts (merge / heap / quick sort).</li><br><li><b>O(n²)</b> — quadratic: two nested loops (bubble / selection / insertion sort).</li><br><li><b>O(n³)</b> — cubic: e.g. naive matrix multiplication, Floyd–Warshall.</li><br><li><b>O(2ⁿ)</b> — exponential: subsets, naive recursive Fibonacci, brute-force SAT.</li><br><li><b>O(n!)</b> — factorial: all permutations, brute-force TSP.</li><br></ul><br><b>Rule of thumb:</b> any polynomial n^k grows slower than any exponential cⁿ, which grows slower than n! <b>Time complexity</b> — What does <i>log n</i> mean in words when analyzing an algorithm? Why does it appear?	<b>In words:</b><br><br><code>log n</code> = the number of times you can <b>halve</b> n (or divide it by any constant factor &gt; 1) before reaching 1.<br><ul><br><li>log₂ 1 024 = 10</li><br><li>log₂ 1 000 000 ≈ 20</li><br><li>log₂ 1 000 000 000 ≈ 30</li><br></ul><br>Extremely slow growth!<br><br><br><b>When it appears:</b><br><br>An algorithm's complexity contains a <code>log n</code> factor whenever each step shrinks the problem to a <b>constant fraction</b> of its previous size — e.g. binary search halves the search range, balanced BST operations cut the depth in half, mergesort recurses on halves.<br><br><br><br><b>Why no base?</b><br><br>Changing the base of a log only multiplies by a constant (log₂ n = log₁₀ n / log₁₀ 2). Constants are dropped in O-notation → <code>O(log n)</code> is base-independent.	Info2::Complexity_and_Correctness

<b>Tree traversal</b> — How do <i>inorder</i>, <i>preorder</i>, and <i>postorder</i> walks work? Give the rule for each, and a small C function for each.	For each traversal you do something at the node (<b>N</b>) and visit the left (<b>L</b>) and right (<b>R</b>) subtrees. The <b>order</b> in which N, L, R are processed is what differs:<br><ul><br><li><b>Inorder</b> = L, N, R → visit left, then output node, then visit right. <i>For a BST this yields sorted order.</i></li><br><li><b>Preorder</b> = N, L, R → output node, then visit left, then visit right. <i>Useful for copying a tree, or printing a prefix expression.</i></li><br><li><b>Postorder</b> = L, R, N → visit left, then visit right, then output node. <i>Useful when children must be processed before the parent</i> (deleting a tree, computing height bottom-up).</li><br></ul><br><b>C code:</b><br><pre><code>struct node {<br>    int value;<br>    struct node *left;<br>    struct node *right;<br>};<br><br>void inorder(struct node *root) {<br>    if (root == NULL) return;<br>    inorder(root-&gt;left);<br>    printf(&quot;%d &quot;, root-&gt;value);<br>    inorder(root-&gt;right);<br>}<br><br>void preorder(struct node *root) {<br>    if (root == NULL) return;<br>    printf(&quot;%d &quot;, root-&gt;value);<br>    preorder(root-&gt;left);<br>    preorder(root-&gt;right);<br>}<br><br>void postorder(struct node *root) {<br>    if (root == NULL) return;<br>    postorder(root-&gt;left);<br>    postorder(root-&gt;right);<br>    printf(&quot;%d &quot;, root-&gt;value);<br>}</code></pre><br><b>Complexity:</b> <code>O(n)</code> for all three (every node is visited once). <b>BST</b> — With a BST, how do you get an ordered output (small to large)? With which traversal?	Use <b>INORDER</b> traversal.<br><br><br><br><b>Why does it work?</b><br><br>By the BST property:<br><ul><br><li>All values in the left subtree are smaller than the root.</li><br><li>All values in the right subtree are larger than the root.</li><br></ul><br>Inorder visits L → N → R, so it prints all smaller values first, then the node, then all larger values. Applied recursively, this gives <b>ascending order</b>.<br><br><br><br><b>For descending order:</b> do a &quot;reverse inorder&quot; → R, N, L.	Info2::Binary_Trees_BST
<b>BST Exam Exercise — Print Two BSTs Sorted</b> — Given two BSTs <code>T1</code> and <code>T2</code> with roots <code>r1</code> and <code>r2</code>, print all elements of both trees in ascending order. You may use one array large enough to hold all <code>n + m</code> elements, but no sorting algorithm.	<b>Idea:</b><br><br>For a BST, <b>inorder traversal</b> visits values in ascending order. So:<br><ol><br><li>Write all values of <code>T1</code> into the array from left to right using inorder.</li><br><li>Write all values of <code>T2</code> into the array after that, also using inorder.</li><br><li>Now the array contains two sorted blocks. To print all values sorted overall, merge the two sorted blocks like in merge sort.</li><br></ol><br>This uses the BST order property instead of a separate sorting algorithm.<br><br><br><br><b>Tree node:</b><br><pre><code>struct TreeNode {<br>    int val;<br>    struct TreeNode *left;<br>    struct TreeNode *right;<br>};</code></pre><br><b>Inorder tree walk with position index:</b><br><pre><code>int a[N];   // large enough for n + m elements<br>int idx;    // next free position in a<br><br>void ITW(struct TreeNode *p) {<br>    // If p is NULL, the current subtree is empty.<br>    // Empty subtrees contribute no values to the array.<br>    if (p != NULL) {<br>        // First visit the left subtree.<br>        // In a BST, all values there are smaller than p-&gt;val.<br>        ITW(p-&gt;left);<br><br>        // Store the current node value at the next free array position.<br>        a[idx] = p-&gt;val;<br><br>        // Move idx to the next free array position.<br>        idx++;<br><br>        // Finally visit the right subtree.<br>        // In a BST, all values there are larger than p-&gt;val.<br>        ITW(p-&gt;right);<br>    }<br>}</code></pre><br><b>Full printing idea:</b><br><pre><code>void printTwoBSTsSorted(struct TreeNode *r1, int n,<br>                        struct TreeNode *r2, int m) {<br>    // Assume a is the global/helper array from above,<br>    // with enough space for all elements from both trees.<br>    // The first n slots will hold T1, the next m slots will hold T2.<br><br>    // Start writing T1 at index 0.<br>    idx = 0;<br><br>    // Inorder traversal writes T1 into a[0..n-1] in sorted order.<br>    ITW(r1);<br><br>    // Start writing T2 right after the block for T1.<br>    idx = n;<br><br>    // Inorder traversal writes T2 into a[n..n+m-1] in sorted order.<br>    ITW(r2);<br><br>    // i scans the first sorted block a[0..n-1].<br>    int i = 0;<br><br>    // j scans the second sorted block a[n..n+m-1].<br>    int j = n;<br><br>    // While both blocks still contain values,<br>    // print the smaller current value and advance that block's cursor.<br>    while (i &lt; n &amp;&amp; j &lt; n + m) {<br>        if (a[i] &lt;= a[j]) {<br>            // a[i] is the next smallest remaining value.<br>            print(a[i]);<br><br>            // Move to the next value in the first block.<br>            i++;<br>        } else {<br>            // a[j] is the next smallest remaining value.<br>            print(a[j]);<br><br>            // Move to the next value in the second block.<br>            j++;<br>        }<br>    }<br><br>    // If T2 is exhausted first, print the remaining values of T1.<br>    while (i &lt; n) {<br>        print(a[i]);<br>        i++;<br>    }<br><br>    // If T1 is exhausted first, print the remaining values of T2.<br>    while (j &lt; n + m) {<br>        print(a[j]);<br>        j++;<br>    }<br>}</code></pre><br><b>Alternative matching the lecture idea:</b><br><br>If you only need to show how values are inserted into an array during traversal, use an inorder tree walk with an index and direction:<br><pre><code>void ITW(struct TreeNode *p, int d) {<br>    // Only process non-empty subtrees.<br>    if (p != NULL) {<br>        // Visit all smaller values first.<br>        ITW(p-&gt;left, d);<br><br>        // Store the current node at the current array position.<br>        a[idx] = p-&gt;val;<br><br>        // Move the array position by d.<br>        // For normal left-to-right writing, d = 1.<br>        idx = idx + d;<br><br>        // Visit all larger values last.<br>        ITW(p-&gt;right, d);<br>    }<br>}</code></pre><br>Here <code>d = 1</code> writes left-to-right. A direction value is useful when you want the same traversal routine to fill different parts of the array.<br><br><br><br><b>Complexity:</b><br><ul><br><li>Each tree node is visited once: <code>O(n + m)</code>.</li><br><li>The merge pass is also <code>O(n + m)</code>.</li><br><li>Total time: <code>O(n + m)</code>.</li><br><li>Extra space: <code>O(n + m)</code> for the array.</li><br></ul>	Info2::Binary_Trees_BST
<b>BST</b> — Search for a value <code>x</code> in a BST in C. Write both the iterative and the recursive version.	<b>Idea:</b> compare <code>x</code> with the current node's value:<br><ul><br><li>equal → found</li><br><li>smaller → go left</li><br><li>larger → go right</li><br><li>NULL → not found</li><br></ul><br><pre><code>struct node {<br>    int value;<br>    struct node *left;<br>    struct node *right;<br>};<br><br>// recursive<br>struct node *bst_search(struct node *root, int x) {<br>    if (root == NULL || root-&gt;value == x) {<br>        return root;<br>    }<br>    if (x &lt; root-&gt;value) {<br>        return bst_search(root-&gt;left, x);<br>    }<br>    return bst_search(root-&gt;right, x);<br>}<br><br>// iterative<br>struct node *bst_search_iter(struct node *root, int x) {<br>    struct node *cur = root;<br>    while (cur != NULL &amp;&amp; cur-&gt;value != x) {<br>        if (x &lt; cur-&gt;value) {<br>            cur = cur-&gt;left;<br>        } else {<br>            cur = cur-&gt;right;<br>        }<br>    }<br>    return cur;   // NULL if x is not in the tree<br>}</code></pre><br><b>Complexity:</b> <code>O(h)</code> → average <code>O(log n)</code>, worst <code>O(n)</code>. <b>BST</b> — How do you find the minimum of a BST? (conceptually, no code)	Walk down the <b>left spine</b> of the tree:<br><ul><br><li>Start at the root.</li><br><li>Keep following the <code>left</code> pointer.</li><br><li>The first node whose <code>left</code> is NULL is the minimum.</li><br></ul><br><b>Why?</b> By the BST property, every left subtree contains only smaller values. So the smallest value in the entire tree must be the <b>leftmost</b> node reachable from the root.<br><br><br><br><b>Maximum:</b> symmetric — walk down the <b>right</b> spine.<br><br><br><br><b>Complexity:</b> <code>O(h)</code>. <b>BST</b> — Code: count the number of occurrences of <code>x</code> in a BST. The function must return how many times <code>x</code> appears in the tree (so it must also handle duplicates correctly).	<b>Idea:</b><br><ul><br><li>If <code>x</code> is smaller than the current node, only the LEFT subtree can contain <code>x</code> → recurse left.</li><br><li>If <code>x</code> is larger than the current node, only the RIGHT subtree can contain <code>x</code> → recurse right.</li><br><li>If <code>x</code> equals the current node's value: count this match as <b>1</b>, and (since the BST may carry duplicates on either side) also continue searching in <b>both</b> subtrees.</li><br></ul><br><pre><code>struct node {<br>    int value;<br>    struct node *left;<br>    struct node *right;<br>};<br><br>int count_occurrences(struct node *root, int x) {<br>    // base case: empty subtree contains 0 occurrences<br>    if (root == NULL) return 0;<br><br>    // x lies strictly left of root → only the left subtree can hold x<br>    if (x &lt; root-&gt;value) {<br>        return count_occurrences(root-&gt;left, x);<br>    }<br><br>    // x lies strictly right of root → only the right subtree can hold x<br>    if (x &gt; root-&gt;value) {<br>        return count_occurrences(root-&gt;right, x);<br>    }<br><br>    // x == root-&gt;value : this node counts as 1.<br>    // duplicates may live in either subtree, so check both.<br>    return 1 + count_occurrences(root-&gt;left, x)<br>             + count_occurrences(root-&gt;right, x);<br>}</code></pre><br><b>Complexity:</b><br><ul><br><li><b>No duplicates of x:</b> <code>O(h)</code> — average <code>O(log n)</code>, worst <code>O(n)</code>.</li><br><li><b>With many duplicates of x:</b> up to <code>O(n)</code> because each match forces recursion into both subtrees.</li><br></ul>	Info2::Binary_Trees_BST
<b>BST</b> — What is the <i>successor</i> of a node? Name the 2 cases for finding the successor (conceptual). Then code it (no parent pointer — walk down from the root).	<b>Successor of x:</b> the node with the <b>smallest value that is still &gt; x's value</b> — equivalently, the node that comes <i>right after x</i> in an inorder traversal.<br><br><br><br><b>2 cases:</b><br><ol><br><li><b>x has a right subtree</b> → the successor is the <b>minimum of the right subtree</b> (its leftmost node).</li><br><li><b>x has no right subtree</b> → walk <b>down from the root</b> toward x. Each time you go LEFT, remember the current node as a candidate successor (<code>succ</code>). The last such candidate when you reach x is the successor. If you never went left, x is the maximum and has no successor.</li><br></ol><br><b>C code:</b><br><pre><code>struct node {<br>    int value;<br>    struct node *left;<br>    struct node *right;<br>};<br><br>struct node *bst_min(struct node *root) {<br>    if (root == NULL) return NULL;<br>    while (root-&gt;left != NULL) {<br>        root = root-&gt;left;<br>    }<br>    return root;<br>}<br><br>// root = root of the whole tree, x = the node whose successor we want<br>struct node *successor(struct node *root, struct node *x) {<br>    // case 1: x has a right subtree → minimum of that right subtree<br>    if (x-&gt;right != NULL) {<br>        return bst_min(x-&gt;right);<br>    }<br><br>    // case 2: no right subtree → walk down from the root toward x,<br>    // remembering the latest node we went LEFT from.<br>    struct node *p    = root;<br>    struct node *succ = NULL;<br><br>    while (p != x) {<br>        if (x-&gt;value &lt; p-&gt;value) {<br>            // x lies in p's left subtree → p is a candidate successor<br>            succ = p;<br>            p = p-&gt;left;<br>        } else {<br>            // x lies in p's right subtree → p is NOT a candidate<br>            p = p-&gt;right;<br>        }<br>    }<br><br>    return succ;   // NULL if x was the maximum (we never went left)<br>}</code></pre><br><b>Why case 2 works:</b> the successor of x must be an ancestor of x for which x sits in its LEFT subtree (so x is smaller than that ancestor, and no smaller ancestor with x in its left subtree exists below it). Each time we go left on the way down, we record the current node — the last one recorded is exactly that lowest ancestor.<br><br><br><br><b>Complexity:</b> <code>O(h)</code>.	Info2::Binary_Trees_BST
<b>BST</b> — Code: how do you insert a <code>struct node *p</code> into a BST? Use a <i>one-step-delayed-pointer</i>. Explain the core idea first.	<b>Core idea (one-step-delayed-pointer):</b><br><ul><br><li>Walk down the tree from the root with a current pointer <code>x</code>.</li><br><li>Keep a second pointer <code>y</code> that is always <b>one step behind</b> <code>x</code> — so <code>y</code> is the parent of <code>x</code>.</li><br><li>When <code>x</code> falls off the tree (becomes NULL), <code>y</code> is exactly the parent of the empty slot.</li><br><li>Attach <code>p</code> as the left or right child of <code>y</code>, depending on how <code>p-&gt;value</code> compares with <code>y-&gt;value</code>.</li><br><li>Return the (possibly new) root <code>r</code>.</li><br></ul><br><b>C code (matches the textbook signature: returns the new root):</b><br><pre><code>struct node {<br>    int value;<br>    struct node *left;<br>    struct node *right;<br>};<br><br>// p = new node to insert (with p-&gt;left = p-&gt;right = NULL)<br>// r = current root of the BST (may be NULL if the tree is empty)<br>// returns the (possibly new) root of the BST<br>struct node *BSTreeInsert(struct node *p, struct node *r) {<br><br>    struct node *y = NULL;   // y is one step delayed → will end up as p's parent<br>    struct node *x = r;      // x walks down from the root<br><br>    // walk down until x runs off the tree<br>    while (x != NULL) {<br>        y = x;   // remember x as the parent of the next step<br><br>        if (x-&gt;value &lt; p-&gt;value) {<br>            // new value belongs to the RIGHT of x → go right<br>            x = x-&gt;right;<br>        } else {<br>            // new value belongs to the LEFT of x → go left<br>            x = x-&gt;left;<br>        }<br>    }<br><br>    // attach p in the correct slot under y<br>    if (y == NULL) {<br>        // tree was empty → p becomes the new root<br>        r = p;<br>    } else if (y-&gt;value &lt; p-&gt;value) {<br>        // p is larger than y → right child of y<br>        y-&gt;right = p;<br>    } else {<br>        // p is smaller (or equal) than y → left child of y<br>        y-&gt;left = p;<br>    }<br><br>    return r;<br>}</code></pre><br><b>Typical call:</b> <code>root = BSTreeInsert(new_node, root);</code><br><br><b>Complexity:</b> <code>O(h)</code>. <b>BST</b> — How do you delete a node in a BST? Explain the 3 cases (conceptual), then code: delete <code>struct node *x</code> from a BST.	<b>3 cases</b> by the number of children of the node to delete:<br><ol><br><li><b>x is a leaf</b> (no children) → simply remove x. Its parent's pointer to it becomes NULL.</li><br><li><b>x has exactly one child</b> → replace x with that child in its parent's pointer slot.</li><br><li><b>x has two children</b> → replace x's <i>value</i> with the value of its <b>inorder successor</b> (= minimum of x's right subtree). Then recursively delete that successor in the right subtree (the successor has at most one child, so this falls into case 1 or 2).</li><br></ol><br><b>C code (line-by-line comments, book style with <code>q = p; p = p-&gt;right; free(q)</code>):</b><br><pre><code>struct node {<br>    int value;<br>    struct node *left;<br>    struct node *right;<br>};<br><br>// helper: smallest node in a subtree (leftmost node)<br>struct node *bst_min(struct node *root) {<br>    // walk down the LEFT spine until there is no more left child<br>    while (root-&gt;left != NULL) root = root-&gt;left;<br>    return root;<br>}<br><br>// deletes the node with value x from the BST whose root pointer is *p.<br>// p is a pointer-to-pointer so we can OVERWRITE *p directly in place;<br>// this writes through to the caller's pointer (e.g. the parent's<br>// left/right slot, or the top-level root pointer).<br>// usage at the top level:   bst_delete(&amp;root, x);<br>void bst_delete(struct node **p, int x) {<br><br>    // 1) base case: x is not in the tree → nothing to do<br>    if (*p == NULL) return;<br><br>    // 2) navigate: same comparisons as in BST search<br>    if (x &lt; (*p)-&gt;value) {<br>        // x must be in the LEFT subtree (BST property)<br>        // recurse on the ADDRESS of the left-child pointer so that<br>        // the recursive call can rewrite it if needed<br>        bst_delete(&amp;(*p)-&gt;left, x);<br><br>    } else if (x &gt; (*p)-&gt;value) {<br>        // x must be in the RIGHT subtree (BST property)<br>        bst_delete(&amp;(*p)-&gt;right, x);<br><br>    } else {<br>        // 3) found the node to delete: (*p)-&gt;value == x<br><br>        // --- CASE 1 + CASE 2 : the node has at most one child ---<br><br>        // case (a): no left child → replace *p with its right child<br>        // (this also handles the leaf case: then (*p)-&gt;right is NULL,<br>        //  so *p becomes NULL — exactly what removing a leaf means)<br>        if ((*p)-&gt;left == NULL) {<br>            struct node *q = *p;          // q = remember the doomed node<br>            *p = (*p)-&gt;right;             // parent slot now points to right child<br>            free(q);                       // delete the old node<br>            return;<br>        }<br><br>        // case (b): no right child → replace *p with its left child<br>        if ((*p)-&gt;right == NULL) {<br>            struct node *q = *p;          // q = remember the doomed node<br>            *p = (*p)-&gt;left;              // parent slot now points to left child<br>            free(q);                       // delete the old node<br>            return;<br>        }<br><br>        // --- CASE 3 : the node has TWO children ---<br><br>        // find the inorder successor: the minimum of the right subtree.<br>        // this node is guaranteed to have NO left child (leftmost) and<br>        // therefore has at most one child → easy to remove later.<br>        struct node *tmp = bst_min((*p)-&gt;right);<br><br>        // copy ONLY the VALUE of the successor into the current node.<br>        // the structural node we want to remove is now &quot;tmp&quot; but its<br>        // value already lives here, so the BST still looks correct.<br>        (*p)-&gt;value = tmp-&gt;value;<br><br>        // delete the successor node from the right subtree.<br>        // since the successor has at most one child, this recursive<br>        // call hits CASE 1 or CASE 2 and terminates quickly.<br>        bst_delete(&amp;(*p)-&gt;right, tmp-&gt;value);<br>    }<br>}</code></pre><br><b>Complexity:</b> <code>O(h)</code>. <b>BST</b> — Code: write a function that determines the height of a BST. What is the asymptotic complexity?	<b>Convention used here:</b><br><ul><br><li>height of an empty tree = <code>-1</code></li><br><li>height of a single-node tree = <code>0</code></li><br></ul><br><pre><code>struct node {<br>    int value;<br>    struct node *left;<br>    struct node *right;<br>};<br><br>int max(int a, int b) {<br>    if (a &gt; b) return a;<br>    return b;<br>}<br><br>int height(struct node *root) {<br>    // base case: empty subtree<br>    if (root == NULL) return -1;<br><br>    // recurse into both subtrees<br>    int lh = height(root-&gt;left);<br>    int rh = height(root-&gt;right);<br><br>    // height of this node = 1 + height of taller child<br>    return 1 + max(lh, rh);<br>}</code></pre><br><b>Complexity:</b><br><ul><br><li><b>Time:</b> <b>O(n)</b> — every node is visited exactly once and does O(1) work.</li><br><li><b>Space:</b> <b>O(h)</b> for the recursion stack (= O(log n) average, O(n) worst).</li><br></ul><br><b>Note on conventions:</b> some courses define height of an empty tree as 0 (then leaf = 1). <b>Search strategies</b> — Explain <i>Breadth-First Search (BFS)</i> vs <i>Depth-First Search (DFS)</i>. What problems is each used for?	<b>BFS — Breadth-First Search:</b><br><ul><br><li>Explores all nodes at the current depth <i>before</i> going deeper.</li><br><li>Visits the tree / graph <b>level by level</b>.</li><br><li>Uses a <b>queue (FIFO)</b>.</li><br></ul><br><b>BFS is used for:</b><br><ul><br><li>Shortest path in an <b>unweighted</b> graph (counted in edges).</li><br><li>Finding the closest match to a source.</li><br><li>Level-order tree traversal.</li><br><li>Connected components in undirected graphs.</li><br></ul><br><b>DFS — Depth-First Search:</b><br><ul><br><li>Goes as <b>deep</b> as possible along each branch, then backtracks.</li><br><li>Uses a <b>stack (LIFO)</b> — explicitly, or implicitly via recursion.</li><br><li>The three tree traversals (inorder, preorder, postorder) are all DFS.</li><br></ul><br><b>DFS is used for:</b><br><ul><br><li>Detecting <b>cycles</b> in a graph.</li><br><li><b>Topological sort</b> of a DAG.</li><br><li>Path existence between two nodes.</li><br><li>All standard tree traversals (inorder / preorder / postorder).</li><br><li>Maze / puzzle solving by exploring full paths.</li><br><li>Finding strongly connected components (Tarjan, Kosaraju).</li><br></ul><br><b>Quick comparison:</b><br><table style=&quot;border-collapse: collapse;&quot;><br><tr><th style=&quot;text-align:left; padding-right:18px;&quot;></th><th style=&quot;text-align:left; padding-right:18px;&quot;>BFS</th><th style=&quot;text-align:left;&quot;>DFS</th></tr><br><tr><td>structure</td><td>queue</td><td>stack / recursion</td></tr><br><tr><td>order</td><td>level by level</td><td>deep first</td></tr><br><tr><td>shortest path (unweighted)</td><td>YES</td><td>no</td></tr><br><tr><td>memory</td><td>O(width)</td><td>O(height)</td></tr><br></table>	Info2::Binary_Trees_BST
<b>AVL</b> — What is the balancing rule behind the AVL tree?	For <b>every</b> node <code>v</code> in the tree, the <b>balance factor</b> satisfies:<br><ul><br><li><code>bf(v) = height(left subtree) − height(right subtree)</code></li><br><li><code>|bf(v)| ≤ 1</code></li><br></ul><br>i.e. the heights of the left and right subtree differ by at most <b>1</b>. The condition must hold <b>recursively</b> for every node.<br><br><br><br><b>Height convention used here:</b><br><ul><br><li><code>height(NULL) = −1</code></li><br><li><code>height(leaf) = 0</code></li><br></ul><br>With this convention, the balance factor of a leaf is <code>0</code> and the height is computed by <code>1 + max(height(left), height(right))</code>. The height of an AVL tree with n nodes is always ___.</i> What is so special about the height of an AVL tree?	<b>Guarantees:</b><br><ul><br><li>AVL trees guarantee <b>O(log n)</b> worst-case complexity for <b>search</b>, <b>insert</b>, and <b>delete</b>.</li><br><li>The height of an AVL tree with <code>n</code> nodes is always <b>Θ(log n)</b>.<br><br>More precisely: <code>h ≤ 1.44 · log₂(n + 2)</code>.</li><br></ul><br><b>Why is this special?</b><br><ul><br><li>A plain BST can degenerate to height <code>O(n)</code> for bad insertion orders (e.g. inserting sorted input → linked list).</li><br><li>The AVL balancing property <b>forces</b> the height to stay logarithmic no matter what sequence of insertions/deletions is applied.</li><br><li>This is what makes search/insert/delete <b>guaranteed</b> <code>O(log n)</code> — not just on average.</li><br></ul>	Info2::AVL_Trees
<b>AVL</b> — What is the structure of an AVL tree node in C? What is the difference compared to a BST node?	An AVL node is a BST node with <b>one extra field</b>: the cached height (or, equivalently, the balance factor).<br><pre><code>struct node {<br>    int value;<br>    int height;            // &lt;-- new: cached height for fast rebalancing<br>    struct node *left;<br>    struct node *right;<br>};<br><br>// returns -1 for NULL so the recursive height formula works for leaves<br>int height(struct node *p) {<br>    if (p == NULL) return -1;<br>    return p-&gt;height;<br>}<br><br>int max(int a, int b) {<br>    if (a &gt; b) return a;<br>    return b;<br>}</code></pre><br><b>Difference vs BST:</b> only the extra <code>height</code> field. Some implementations store the <i>balance factor</i> directly instead — both approaches work; storing the height is slightly more flexible.	Info2::AVL_Trees
<b>AVL</b> — When do you perform a right rotation? Code the algorithm for right rotation.	<b>When?</b> When a node's <b>LEFT subtree is too tall</b> and the left child is itself <i>left-heavy or balanced</i> (LL case). A right rotation pulls the left child upward.<br><br><br><br><b>Picture:</b><br><pre><code>     y                    x<br>    / \                  / \<br>   x   T3       →       T1  y<br>  / \                       / \<br> T1  T2                    T2  T3</code></pre><br><b>C code:</b><br><pre><code>struct node *right_rotate(struct node *y) {<br>    struct node *x  = y-&gt;left;<br>    struct node *T2 = x-&gt;right;<br><br>    // perform rotation: x moves up, y moves down to x's right<br>    x-&gt;right = y;<br>    y-&gt;left  = T2;<br><br>    // update heights — lowest node FIRST<br>    y-&gt;height = 1 + max(height(y-&gt;left), height(y-&gt;right));<br>    x-&gt;height = 1 + max(height(x-&gt;left), height(x-&gt;right));<br><br>    return x;   // x is the new root of this subtree<br>}</code></pre>	Info2::AVL_Trees
<b>AVL</b> — When do you perform a left rotation? Code the algorithm for left rotation.	<b>When?</b> When a node's <b>RIGHT subtree is too tall</b> and the right child is itself <i>right-heavy or balanced</i> (RR case). A left rotation pulls the right child upward.<br><br><br><br><b>Picture:</b><br><pre><code>    x                        y<br>   / \                      / \<br>  T1  y           →        x   T3<br>     / \                  / \<br>    T2  T3               T1  T2</code></pre><br><b>C code:</b><br><pre><code>struct node *left_rotate(struct node *x) {<br>    struct node *y  = x-&gt;right;<br>    struct node *T2 = y-&gt;left;<br><br>    // perform rotation: y moves up, x moves down to y's left<br>    y-&gt;left  = x;<br>    x-&gt;right = T2;<br><br>    // update heights — lowest node FIRST<br>    x-&gt;height = 1 + max(height(x-&gt;left), height(x-&gt;right));<br>    y-&gt;height = 1 + max(height(y-&gt;left), height(y-&gt;right));<br><br>    return y;   // y is the new root of this subtree<br>}</code></pre>	Info2::AVL_Trees
<b>AVL</b> — When do you perform a left-right rotation? When a right-left rotation? Code both fully.	<b>LR rotation — when?</b> When a node's <b>LEFT subtree is too tall</b> but the <b>left child is RIGHT-heavy</b>. A single right rotation is not enough — we first <i>left-rotate</i> the left child (which turns LR into LL), then <i>right-rotate</i> the node.<br><br><br><br><b>LR picture:</b><br><pre><code>     z                  z                    y<br>    / \                / \                  / \<br>   x   T4             y   T4               x   z<br>  / \      →         / \         →        / \ / \<br> T1  y              x   T3              T1 T2 T3 T4<br>    / \            / \<br>   T2  T3         T1  T2</code></pre><br><b>LR code:</b><br><pre><code>struct node *left_right_rotate(struct node *p) {<br>    // step 1: left-rotate the left child → now LL shape<br>    p-&gt;left = left_rotate(p-&gt;left);<br><br>    // step 2: right-rotate p<br>    return right_rotate(p);<br>}</code></pre><br><br><br><b>RL rotation — when?</b> When a node's <b>RIGHT subtree is too tall</b> but the <b>right child is LEFT-heavy</b>. Mirror of LR: first <i>right-rotate</i> the right child (which turns RL into RR), then <i>left-rotate</i> the node.<br><br><br><br><b>RL picture:</b><br><pre><code>   z                    z                       y<br>  / \                  / \                     / \<br> T1  x                T1  y                   z   x<br>    / \      →           / \       →        / \ / \<br>   y   T4               T2  x              T1 T2 T3 T4<br>  / \                       / \<br> T2  T3                    T3  T4</code></pre><br><b>RL code:</b><br><pre><code>struct node *right_left_rotate(struct node *p) {<br>    // step 1: right-rotate the right child → now RR shape<br>    p-&gt;right = right_rotate(p-&gt;right);<br><br>    // step 2: left-rotate p<br>    return left_rotate(p);<br>}</code></pre><br><b>In practice</b> these are usually inlined inside <code>AVLrebalance</code> rather than written as standalone functions. <b>AVL</b> — What are the 5 steps for inserting an element in an AVL tree?	<ol><br><li><b>Insert like in a normal BST</b> — find the right slot and attach the new node as a leaf.</li><br><li><b>Move back up the recursion path</b> — every recursive call now returns to an ancestor of the inserted node.</li><br><li><b>Update heights</b> — recompute the height of each ancestor:<br><br><code>p-&gt;height = 1 + max(height(p-&gt;left), height(p-&gt;right));</code></li><br><li><b>Compute the balance factor</b> — <code>bf = height(p-&gt;left) − height(p-&gt;right);</code></li><br><li><b>Fix imbalances with rotations</b> — if <code>|bf| &gt; 1</code>, apply the matching rotation:<br><br>LL → right-rotate, RR → left-rotate, LR → left + right, RL → right + left.</li><br></ol><br><b>Important:</b> after an insertion, <b>at most ONE rotation (single or double)</b> is needed to fix the entire tree. <b>AVL</b> — There are 3 cases of deletion in an AVL tree. Name them. How does deletion differ from insertion regarding rebalancing?	The <b>3 deletion cases</b> are the same as for a plain BST:<br><ol><br><li><b>Node is a leaf</b> → simply remove it.</li><br><li><b>Node has exactly one child</b> → replace it with its child.</li><br><li><b>Node has two children</b> → replace its <i>value</i> with the value of its inorder successor (the minimum of the right subtree), then delete that successor in the right subtree (which falls into case 1 or 2).</li><br></ol><br><b>Difference vs insertion regarding rebalancing:</b><br><ul><br><li><b>After insertion:</b> at most ONE rebalancing along the path back to the root is enough.</li><br><li><b>After deletion:</b> up to <b>O(log n)</b> rebalancings — the height can shrink at the deleted spot, and that shrink can propagate upward all the way to the root, forcing many ancestors to be rebalanced.</li><br></ul><br>That's why the AVL deletion algorithm <i>always</i> rebalances every ancestor on the way back up, not just the first imbalanced one. <b>AVL</b> — Code: one-liner to update the height of a node for rebalancing.	<pre><code>p-&gt;height = 1 + max(height(p-&gt;left), height(p-&gt;right));</code></pre><br>With the helper:<br><pre><code>int height(struct node *p) {<br>    if (p == NULL) return -1;<br>    return p-&gt;height;<br>}</code></pre><br><b>Why it works:</b> a leaf has <code>height(NULL) = −1</code> for both children, so its height becomes <code>1 + max(−1, −1) = 0</code>. Every internal node is 1 higher than its taller child.	Info2::AVL_Trees
<b>AVL</b> — Write the full rebalancing pseudocode <code>AVLrebalance(p)</code>. It must first update the height of <code>p</code>, contain all 4 cases (<b>LL, RR, LR, RL</b>), and return <code>p</code> (or the new subtree root after rotation).	<pre><code>struct node *AVLrebalance(struct node *p) {<br>    if (p == NULL) return NULL;<br><br>    // 1) update height of p<br>    p-&gt;height = 1 + max(height(p-&gt;left), height(p-&gt;right));<br><br>    // 2) compute balance factor of p<br>    int bf = height(p-&gt;left) - height(p-&gt;right);<br><br>    // 3) LEFT side too heavy  (bf &gt; 1)<br>    if (bf &gt; 1) {<br>        // LR case: left child is right-heavy<br>        // → first left-rotate the left child (turns LR into LL)<br>        if (height(p-&gt;left-&gt;left) &lt; height(p-&gt;left-&gt;right)) {<br>            p-&gt;left = left_rotate(p-&gt;left);<br>        }<br>        // LL case (or after LR conversion above): right-rotate p<br>        return right_rotate(p);<br>    }<br><br>    // 4) RIGHT side too heavy (bf &lt; -1)<br>    if (bf &lt; -1) {<br>        // RL case: right child is left-heavy<br>        // → first right-rotate the right child (turns RL into RR)<br>        if (height(p-&gt;right-&gt;right) &lt; height(p-&gt;right-&gt;left)) {<br>            p-&gt;right = right_rotate(p-&gt;right);<br>        }<br>        // RR case (or after RL conversion above): left-rotate p<br>        return left_rotate(p);<br>    }<br><br>    // 5) already balanced → nothing to do<br>    return p;<br>}</code></pre><br><b>Complexity:</b> <code>O(1)</code> per call (a constant number of pointer rewires + height updates). <b>AVL</b> — How do insertion and deletion work conceptually in an AVL tree? Give pseudocode for both.	<b>AVL Insertion — conceptual:</b><br><ol><br><li>Insert like in a normal BST.</li><br><li>On the way back up the recursion, update heights and call <code>AVLrebalance</code> on every ancestor.</li><br><li><i>At most ONE</i> rotation needed in total.</li><br></ol><br><pre><code>struct node *AVLInsert(struct node *root, int x) {<br>    // 1) standard BST insertion (no duplicates)<br>    if (root == NULL) {<br>        struct node *p = malloc(sizeof(struct node));<br>        p-&gt;value  = x;<br>        p-&gt;height = 0;          // fresh leaf has height 0<br>        p-&gt;left   = NULL;<br>        p-&gt;right  = NULL;<br>        return p;<br>    }<br>    if (x &lt; root-&gt;value) {<br>        root-&gt;left  = AVLInsert(root-&gt;left,  x);<br>    } else if (x &gt; root-&gt;value) {<br>        root-&gt;right = AVLInsert(root-&gt;right, x);<br>    } else {<br>        return root;             // duplicate → ignore<br>    }<br><br>    // 2) rebalance on the way up<br>    return AVLrebalance(root);<br>}</code></pre><br><br><b>AVL Deletion — conceptual:</b><br><ol><br><li>Delete like in a normal BST (the 3 cases).</li><br><li>On the way back up, update heights and call <code>AVLrebalance</code> on every ancestor.</li><br><li><i>Up to O(log n)</i> rotations possible because the shrink can propagate.</li><br></ol><br><pre><code>// deletes the node with value x from the AVL tree whose root is *p.<br>// p is a pointer-to-pointer so we can OVERWRITE *p in place; the<br>// recursion threads addresses through &amp;(*p)-&gt;left / &amp;(*p)-&gt;right.<br>// usage at the top level:  AVLDelete(&amp;root, x);<br>void AVLDelete(struct node **p, int x) {<br><br>    // 1) base case: x is not in the tree → nothing to do<br>    if (*p == NULL) return;<br><br>    // 2) navigate / delete (no early return — we want to fall through<br>    //    to the rebalance step at the bottom)<br>    if (x &lt; (*p)-&gt;value) {<br>        AVLDelete(&amp;(*p)-&gt;left, x);<br><br>    } else if (x &gt; (*p)-&gt;value) {<br>        AVLDelete(&amp;(*p)-&gt;right, x);<br><br>    } else {<br>        // found the node to delete<br><br>        // case 1 + 2: at most one child<br>        if ((*p)-&gt;left == NULL) {<br>            struct node *q = *p;          // remember doomed node<br>            *p = (*p)-&gt;right;             // parent slot → right child<br>            free(q);<br>        } else if ((*p)-&gt;right == NULL) {<br>            struct node *q = *p;<br>            *p = (*p)-&gt;left;              // parent slot → left child<br>            free(q);<br>        } else {<br>            // case 3: two children — copy successor value, then delete it<br>            struct node *tmp = bst_min((*p)-&gt;right);<br>            (*p)-&gt;value = tmp-&gt;value;<br>            AVLDelete(&amp;(*p)-&gt;right, tmp-&gt;value);<br>        }<br>    }<br><br>    // 3) rebalance on the way up (only if there is still a node here).<br>    //    AVLrebalance updates the height and applies LL/LR/RR/RL fixes.<br>    if (*p != NULL) {<br>        *p = AVLrebalance(*p);<br>    }<br>}</code></pre><br><b>Total time complexity:</b> <code>O(log n)</code> for both — <code>O(1)</code> rebalance work per level × <code>O(log n)</code> levels. <b>HT</b> — Two methods of hashing: <b>division</b> and <b>multiplication</b>. <b>Matrix Multiplication DP</b> — How can we find the best parenthesis split for matrix multiplication with a helper matrix? What values are calculated there? Code the DP solution for the minimum multiplication cost in C, iteratively and recursively. Explain the difference.	<b>Problem:</b><br><br>Given matrices<br><pre><code>A1, A2, ..., An</code></pre><br>we want to choose the parentheses so that the number of scalar multiplications is minimal.<br><br><br><br>If matrix <code>Ai</code> has size <code>d[i-1] × d[i]</code>, then multiplying<br><pre><code>(Ai ... Ak) · (A(k+1) ... Aj)</code></pre><br>costs:<br><pre><code>M[i][k] + M[k+1][j] + d[i-1] * d[k] * d[j]</code></pre><br><b>Helper matrix:</b><br><ul><br><li><code>M[i][j]</code> stores the <b>minimum cost</b> to multiply matrices <code>Ai ... Aj</code>.</li><br><li><code>split[i][j]</code> can store the best split position <code>k</code>, so we know where to put the parentheses.</li><br><li>Base case: <code>M[i][i] = 0</code>, because one matrix alone needs no multiplication.</li><br></ul><br><b>Variable meanings:</b><br><ul><br><li><code>d[]</code>: dimension array. Matrix <code>Ai</code> has size <code>d[i-1] × d[i]</code>.</li><br><li><code>n</code>: number of matrices, so <code>d</code> has length <code>n + 1</code>.</li><br><li><code>i, j</code>: first and last matrix index of the current subchain.</li><br><li><code>k</code>: split point; it separates <code>Ai..Ak</code> from <code>A(k+1)..Aj</code>.</li><br><li><code>q</code>: cost of one candidate split.</li><br></ul><br><b>Iterative bottom-up version:</b><br><pre><code>#include &lt;limits.h&gt;<br><br>int matrix_chain_iterative(int d[], int n) {<br>    // M[i][j] = minimum cost to multiply Ai ... Aj<br>    int M[n + 1][n + 1];<br><br>    // split[i][j] = best k where Ai ... If that group has sum <code>x</code>, the other group has sum <code>S - x</code>, so the final value is:<br><pre><code>(S - x) - x = S - 2x</code></pre><br>We want the largest reachable <code>x &lt;= S/2</code>.<br><br><br><br><b>DP meaning:</b><br><br>Let <code>dp[i][j]</code> be the maximum sum not larger than <code>j</code> that can be built using the first <code>i</code> elements <code>A[0..i-1]</code>.<br><br><br><br><b>Variable meanings:</b><br><ul><br><li><code>A[]</code>: input array of positive integers.</li><br><li><code>n</code>: number of elements.</li><br><li><code>S</code>: total sum of all elements.</li><br><li><code>half</code>: target upper bound <code>floor(S/2)</code>.</li><br><li><code>dp[i][j]</code>: best reachable sum <code>&lt;= j</code> using the first <code>i</code> values.</li><br><li><code>take</code>: result if we put <code>A[i-1]</code> into the selected group.</li><br><li><code>skip</code>: result if we do not select <code>A[i-1]</code>.</li><br></ul><br>For element <code>A[i-1]</code>:<br><ul><br><li>If <code>A[i-1] &lt;= j</code>, either take it or skip it.</li><br><li>If <code>A[i-1] &gt; j</code>, it cannot be part of the subsequence, so we skip it.</li><br></ul><br><b>C code:</b><br><pre><code>int max(int a, int b) {<br>    // Return the larger of two candidate subset sums.<br>    return a &gt; b ? a : b;<br>}<br><br>int calculate(int A[], int n) {<br>    // S will store the total sum of all numbers in A.<br>    int S = 0;<br><br>    // Add every array element to the total sum S.<br>    for (int i = 0; i &lt; n; i++) {<br>        // Include A[i] in the total.<br>        S += A[i];<br>    }<br><br>    // We only need subset sums up to floor(S / 2).<br>    // A subset larger than half would just mirror a smaller subset on the other side.<br>    int half = S / 2;<br><br>    // dp[i][j] = largest reachable sum &lt;= j<br>    // using only the first i elements A[0..i-1].<br>    int dp[n + 1][half + 1];<br><br>    // First column:<br>    // If the allowed sum is 0, the best reachable sum is always 0.<br>    for (int i = 0; i &lt;= n; i++) {<br>        dp[i][0] = 0;<br>    }<br><br>    // First row:<br>    // With 0 elements, we cannot build any positive sum.<br>    // The best reachable sum is therefore 0 for every capacity j.<br>    for (int j = 0; j &lt;= half; j++) {<br>        dp[0][j] = 0;<br>    }<br><br>    // Build the table row by row.<br>    // Row i means: we may use A[0], ..., A[i-1].<br>    for (int i = 1; i &lt;= n; i++) {<br>        // Column j means: selected sum may not exceed j.<br>        for (int j = 1; j &lt;= half; j++) {<br>            // Check whether the current element A[i-1] fits into capacity j.<br>            if (j &gt;= A[i - 1]) {<br>                // Option 1: take A[i-1].<br>                // Then the remaining allowed sum is j - A[i-1].<br>                int take = dp[i - 1][j - A[i - 1]] + A[i - 1];<br><br>                // Option 2: skip A[i-1].<br>                // Then the best value is the one from the previous row.<br>                int skip = dp[i - 1][j];<br><br>                // Choose the larger reachable sum that still does not exceed j.<br>                dp[i][j] = max(take, skip);<br>            } else {<br>                // A[i-1] is too large to fit into capacity j.<br>                // We must skip it and copy the previous row.<br>                dp[i][j] = dp[i - 1][j];<br>            }<br>        }<br>    }<br><br>    // x is the largest reachable subset sum not larger than S/2.<br>    // This makes the two final group sums as balanced as possible.<br>    int x = dp[n][half];<br><br>    // One group has sum x.<br>    // The other group has sum S - x.<br>    // The smallest possible final Minus value is their difference.<br>    return S - 2 * x;<br>}</code></pre><br><b>Complexity:</b> <code>O(nS)</code> time and <code>O(nS)</code> space, more precisely <code>O(n · floor(S/2))</code>. <b>HT — Chaining</b> — What is the load factor for chaining? What is the search complexity? What is the expected number of probes? <b>Bonus:</b> what benefits and disadvantages would you expect by using a <i>binary search tree</i> instead of a linked list to handle hash-table overflows?	<b>Chaining:</b> each slot holds a linked list (&quot;chain&quot;) of all keys that hash to that slot.<br><br><br><br><b>Load factor:</b><br><pre><code>α = n / m</code></pre><br>where <code>n</code> = number of stored keys and <code>m</code> = number of buckets. For chaining <b>α can exceed 1</b> (chains can be arbitrarily long).<br><br><br><br><b>Search complexity:</b><br><ul><br><li><b>Average:</b> <code>O(1 + α)</code> — constant hashing time plus a walk through one chain of expected length α.</li><br><li><b>Worst case:</b> <code>O(n)</code> — if all keys hash to the same bucket, one chain holds everything.</li><br></ul><br><b>Expected number of probes:</b><br><ul><br><li><b>Unsuccessful search:</b> <code>≈ α</code> (must walk the full chain).</li><br><li><b>Successful search:</b> <code>≈ 1 + α / 2</code> (on average we find the key in the middle of the chain).</li><br></ul><br><br><br><b>Bonus — BST instead of linked list for the chains:</b><br><br><br><br><b>Benefits:</b><br><ul><br><li><b>Faster lookup inside a heavy bucket:</b> a linked list takes <code>O(chain length)</code>, a balanced BST (e.g. AVL) takes <code>O(log(chain length))</code>.</li><br><li><b>Much better worst case:</b> if every key collides into one bucket, the worst case drops from <code>O(n)</code> to <code>O(log n)</code>.</li><br><li><b>Ordered traversal inside a bucket</b> becomes possible (useful for range queries).</li><br></ul><br><b>Disadvantages:</b><br><ul><br><li><b>More memory per node:</b> instead of one <code>next</code> pointer, a BST node needs <code>left</code>, <code>right</code> (and a height field for AVL).</li><br><li><b>More code complexity:</b> insertion, deletion and (for AVL) rebalancing must be implemented per bucket.</li><br><li><b>Pointless if α is small:</b> when chains are short (e.g. average length 1–2), the constant overhead of trees costs more than it saves — a plain list wins in practice.</li><br></ul><br><b>Rule of thumb:</b> use trees as the bucket structure only when collisions are very heavy (e.g. Java's <code>HashMap</code> switches a bucket from a linked list to a red-black tree once the bucket has &gt; 8 entries). <b>HT — Open addressing</b> — How does it work (principle)? What is the load factor? How do <b>insert</b>, <b>search</b>, and <b>delete</b> work?	<b>Principle:</b><br><ul><br><li><b>All elements are stored directly in the table array</b> — no linked lists, no chains.</li><br><li>On a collision, we <b>probe</b> for the next slot using a probe sequence: <code>h(k, 0), h(k, 1), h(k, 2), …</code></li><br><li><b>Insert:</b> probe until we find an EMP or DEL slot.</li><br><li><b>Search:</b> probe until we find the key (OCC + same key) or hit an EMP slot (then key is not in the table).</li><br><li><b>Delete:</b> mark the slot as DEL (tombstone), <i>not</i> EMP — otherwise we would break the probe path of other keys.</li><br></ul><br><b>Load factor:</b><br><pre><code>α = n / m,    with    α ≤ 1</code></pre><br><b>α cannot exceed 1</b> because every slot holds at most one element. <b>HT</b> — Deletion in a hash table: why can we NOT just set a slot to EMP? Code deletion in C. <b>HT</b> — Code: insert a key in a hash table with <b>linear probing</b>.	<pre><code>// inserts (k, v) into the hash table H.<br>// returns the slot index on success, -1 if the table is full.<br>int hash_insert(struct hash_table *H, int k, int v) {<br>    // i = probe number;   idx = slot to check at this probe<br>    for (int i = 0; i &lt; H-&gt;m; i++) {<br>        int idx = (h(k) + i) % H-&gt;m;<br><br>        // we can reuse EMP slots AND DEL tombstones<br>        if (H-&gt;table[idx].status != OCC) {<br>            H-&gt;table[idx].key    = k;<br>            H-&gt;table[idx].value  = v;<br>            H-&gt;table[idx].status = OCC;<br>            return idx;<br>        }<br><br>        // OCC slot → collision, advance the probe<br>    }<br>    return -1;   // table is full<br>}</code></pre><br><b>Note:</b> this assumes <code>k</code> is not already in the table. <b>HT</b> — Code: search for a key <code>k</code> in a hash table with <b>linear probing</b>.	<pre><code>// searches for key k in the hash table H.<br>// returns the slot index if found, -1 otherwise.<br>int hash_search(struct hash_table *H, int k) {<br>    for (int i = 0; i &lt; H-&gt;m; i++) {<br>        int idx = (h(k) + i) % H-&gt;m;<br><br>        // EMP means: slot was never used. linear probing would have<br>        // placed k HERE if it had ever been inserted → it isn't in<br>        // the table → stop searching.<br>        if (H-&gt;table[idx].status == EMP) return -1;<br><br>        // OCC and key matches → found<br>        if (H-&gt;table[idx].status == OCC &amp;&amp; H-&gt;table[idx].key == k) {<br>            return idx;<br>        }<br><br>        // DEL → skip and continue probing (don't stop here!)<br>    }<br>    return -1;   // searched the whole table, key not found<br>}</code></pre><br><b>Key detail:</b> stop on EMP but <i>never</i> on DEL — that is exactly why we need the DEL tombstone. <b>HT Exercise — Duplicates / Intersection</b> — You are given two arrays <code>A</code> and <code>B</code> with lengths <code>n</code> and <code>m</code>, containing strictly positive integers. The algorithm should run in <code>O(n + m)</code>.	<b>Idea:</b><br><ul><br><li>Store all elements of <code>A</code> in a hash table.</li><br><li>Then scan <code>B</code>. Then later occurrences of the same value in <code>B</code> will not be printed again.<br><br><br><br><b>Pseudocode:</b><br><pre><code>void print_intersection(int A[], int n, int B[], int m) {<br>    HT H;<br>    init_HT(&amp;H);<br><br>    // put every element of A into the hash table<br>    for (int i = 0; i &lt; n; i++) {<br>        insert(&amp;H, A[i]);<br>    }<br><br>    // check which elements of B also occur in A<br>    for (int j = 0; j &lt; m; j++) {<br>        if (search(&amp;H, B[j]) != -1) {<br>            printf(&quot;%d &quot;, B[j]);<br><br>            // optional but useful: prevents printing duplicates<br>            // if B contains the same common element several times<br>            delete(&amp;H, B[j]);<br>        }<br>    }<br>}</code></pre><br><b>Complexity argument:</b><br><ul><br><li>Building the hash table from <code>A</code>: expected <code>O(n)</code>.</li><br><li>Scanning <code>B</code> and searching each element: expected <code>O(m)</code>.</li><br><li>Total expected time: <b><code>O(n + m)</code></b>.</li><br><li>Extra space: <code>O(n)</code> for the hash table.</li><br></ul>	Info2::Hash_Tables
<b>HT Exercise — Target Sum</b> — You are given an array <code>A</code> with <code>n</code> strictly positive, distinct integers and a target sum <code>t</code>. Use a hash table to decide whether any two integers in <code>A</code> form the target sum <code>t</code>. Return <code>1</code> if possible and <code>0</code> otherwise. The algorithm should run in <code>O(n)</code>.	<b>Idea:</b><br><ul><br><li>For each element <code>x = A[i]</code>, the partner we need is <code>t − x</code>.</li><br><li>Use a hash table to remember elements we have already seen.</li><br><li>Before inserting <code>x</code>, search for <code>t − x</code>.</li><br><li>If the complement is already in the hash table, we found a valid pair.</li><br></ul><br><b>Why search before insert?</b> Because we must use <b>two different elements</b>. If we inserted <code>x</code> first, then for <code>t = 2x</code> we might accidentally match <code>x</code> with itself. The array is distinct, but this order is still the clean invariant.<br><br><br><br><b>Pseudocode:</b><br><pre><code>int target_sum(int A[], int n, int t) {<br>    HT H;<br>    init_HT(&amp;H);<br><br>    for (int i = 0; i &lt; n; i++) {<br>        int x = A[i];<br>        int needed = t - x;<br><br>        // have we already seen the required partner?<br>        if (search(&amp;H, needed) != -1) {<br>            return 1;<br>        }<br><br>        // remember x for later elements<br>        insert(&amp;H, x);<br>    }<br><br>    return 0;<br>}</code></pre><br><b>Small example:</b> if <code>A = [3, 9, 2, 8]</code> and <code>t = 11</code>, then when <code>x = 2</code>, <code>needed = 9</code>. Since 9 was inserted earlier, return <code>1</code>.<br><br><br><br><b>Complexity argument:</b><br><ul><br><li>Each element is searched once and inserted once.</li><br><li>Hash table operations are expected <code>O(1)</code>.</li><br><li>Total expected time: <b><code>O(n)</code></b>.</li><br><li>Extra space: <code>O(n)</code>.</li><br></ul>	Info2::Hash_Tables
