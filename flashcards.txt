"<b>Bubble Sort</b> — Explain how it works (steps, ~4 bullets), code it in C, and state time &amp; space complexity (best / avg / worst, space)."	"<b>Principle (steps):</b>
<ol>
<li>Walk through the array from left to right.</li>
<li>For every adjacent pair, if the left element is greater than the right, swap them.</li>
<li>After one full pass, the largest unsorted element has 'bubbled up' to the end → it is now in its final position.</li>
<li>Repeat for the remaining unsorted prefix. After <i>i</i> passes the last <i>i</i> elements are sorted.</li>
</ol>
<b>C code:</b>
<pre><code>void bubble_sort(int a[], int n) {
    // i counts how many passes we have done
    // after pass i the last i elements are already in place
    for (int i = 0; i &lt; n - 1; i++) {
        // j stops at n-1-i because the last i elements are already sorted
        for (int j = 0; j &lt; n - 1 - i; j++) {
            if (a[j] &gt; a[j+1]) {
                int tmp = a[j];
                a[j]    = a[j+1];
                a[j+1]  = tmp;
            }
        }
    }
}</code></pre>
<b>Complexity:</b>
<ul>
<li>Time — Best / Average / Worst: <b>O(n²)</b>.</li>
<li>Space: <b>O(1)</b>, in-place.</li>
</ul>"	Info2::Sorting
"<b>Selection Sort</b> — Explain how it works (steps, ~4 bullets), code it in C, and state time &amp; space complexity (best / avg / worst, space)."	"<b>Principle (steps):</b>
<ol>
<li>Split the array conceptually into a sorted prefix (initially empty) and an unsorted suffix.</li>
<li>Scan the unsorted suffix to find the minimum element.</li>
<li>Swap that minimum with the first element of the unsorted suffix → the sorted prefix grows by one.</li>
<li>Repeat until the unsorted suffix is empty. Exactly <i>n − 1</i> swaps in total.</li>
</ol>
<b>C code:</b>
<pre><code>void selection_sort(int a[], int n) {
    // i = boundary; the sorted prefix is a[0..i-1]
    for (int i = 0; i &lt; n - 1; i++) {
        // min_idx = index of the smallest element found so far in the unsorted part
        int min_idx = i;
        // scan the unsorted suffix [i+1, n)
        for (int j = i + 1; j &lt; n; j++) {
            if (a[j] &lt; a[min_idx]) {
                min_idx = j;
            }
        }
        // put the minimum at position i (skip swap if it's already there)
        if (min_idx != i) {
            int tmp     = a[i];
            a[i]        = a[min_idx];
            a[min_idx]  = tmp;
        }
    }
}</code></pre>
<b>Complexity:</b>
<ul>
<li>Time — Best / Average / Worst: <b>O(n²)</b> (always scans the full suffix, no early exit).</li>
<li>Space: <b>O(1)</b>, in-place.</li>
<li>Nice property: only <b>O(n)</b> swaps total → good when writes are expensive.</li>
</ul>"	Info2::Sorting
"<b>Insertion Sort</b> — Explain how it works (steps, ~5 bullets), code it in C, and state time &amp; space complexity (best / avg / worst, space)."	"<b>Principle (steps):</b>
<ol>
<li>Treat the first element as a sorted sub-array of length 1.</li>
<li>Take the next element (the <i>key</i>) from the unsorted part.</li>
<li>Shift every element of the sorted part that is greater than the key one position to the right.</li>
<li>Insert the key into the gap so the sorted part is sorted again.</li>
<li>Repeat for every remaining element. Sorted region grows by 1 each iteration.</li>
</ol>
<b>C code:</b>
<pre><code>void insertion_sort(int a[], int n) {
    // i = first index of the unsorted part; sorted part is a[0..i-1]
    for (int i = 1; i &lt; n; i++) {
        // key = element we are inserting into the sorted prefix
        int key = a[i];
        // j walks left through the sorted prefix
        int j   = i - 1;
        // shift every element greater than key one position to the right
        while (j &gt;= 0 &amp;&amp; a[j] &gt; key) {
            a[j+1] = a[j];
            j--;
        }
        // j+1 is the correct slot for key (the gap left by the shifting)
        a[j+1] = key;
    }
}</code></pre>
<b>Complexity:</b>
<ul>
<li>Time — Best: <b>O(n)</b> (already sorted, inner while exits immediately). Average / Worst: <b>O(n²)</b>.</li>
<li>Space: <b>O(1)</b>, in-place.</li>
<li>Excellent for <b>small</b> or <b>nearly-sorted</b> arrays.</li>
</ul>"	Info2::Sorting
"<b>Quick Sort</b> — Explain how it works (steps, ~4 bullets), code it in C (Hoare partition), and state time &amp; space complexity (best / avg / worst, space)."	"<b>Principle (steps):</b>
<ol>
<li>Base case: a sub-array of length ≤ 1 is sorted → return.</li>
<li>Pick a <i>pivot</i> (we use <code>a[lo]</code> here; see the pivot-choice card for better options).</li>
<li><b>Partition (Hoare):</b> two pointers walk towards each other from both ends, swapping out-of-place elements, until they cross. Result: every element left of the split is ≤ pivot, every element right of the split is ≥ pivot.</li>
<li>Recursively quicksort both halves. With Hoare you recurse on <code>[lo, p]</code> and <code>[p+1, hi]</code> (note: <code>p</code>, not <code>p−1</code>, because the pivot is not guaranteed to land at index <code>p</code>).</li>
</ol>
<b>C code (Hoare partition):</b>
<pre><code>static void swap(int *x, int *y) {
    int tmp = *x; *x = *y; *y = tmp;
}

// Hoare partition: returns an index p such that
//   every element in a[lo..p]   is &lt;= pivot,
//   every element in a[p+1..hi] is &gt;= pivot.
// (The pivot itself can end up anywhere on the left side.)
int hoare_partition(int a[], int lo, int hi) {
    // pivot value (any choice works; we take the first element)
    int pivot = a[lo];
    // i = left pointer, starts just OUTSIDE the range; will move right
    int i = lo - 1;
    // j = right pointer, starts just OUTSIDE the range; will move left
    int j = hi + 1;
    while (1) {
        // advance i until we find an element NOT smaller than pivot
        do { i++; } while (a[i] &lt; pivot);
        // advance j until we find an element NOT greater than pivot
        do { j--; } while (a[j] &gt; pivot);
        // if the pointers crossed, the partition is complete
        if (i &gt;= j) return j;
        // otherwise a[i] and a[j] are on the wrong sides → swap them
        swap(&amp;a[i], &amp;a[j]);
    }
}

void quick_sort(int a[], int lo, int hi) {
    if (lo &lt; hi) {
        int p = hoare_partition(a, lo, hi);
        // with Hoare we use p (NOT p-1) for the left recursive call
        quick_sort(a, lo, p);
        quick_sort(a, p + 1, hi);
    }
}</code></pre>
<b>Complexity:</b>
<ul>
<li>Time — Best / Average: <b>O(n log n)</b>. Worst: <b>O(n²)</b> (bad pivot every time, e.g. always picking the smallest / largest element).</li>
<li>Space: <b>O(log n)</b> recursion stack on average, <b>O(n)</b> in the worst case. In-place (no extra array).</li>
<li>In practice the fastest comparison sort due to good cache behavior and small constants.</li>
</ul>"	Info2::Sorting
"<b>Quick Sort</b> — What is the best choice for a good pivot, and why? (3 practical choices + why pivot choice matters)"	"<b>Ideal pivot:</b> the <i>median</i> of the sub-array → both partitions have size ≈ n/2 → recursion depth ≈ log n → total <b>O(n log n)</b>.
But finding the true median costs an extra O(n) per call → too expensive in practice.

<b>Three practical pivot strategies:</b>
<ol>
<li><b>Random pivot</b> — pick a uniformly random index in <code>[lo, hi]</code>. Defeats adversarial inputs (sorted / reverse-sorted arrays). Expected <b>O(n log n)</b>, worst case still possible but extremely unlikely.</li>
<li><b>Median-of-three</b> — take the median of <code>a[lo]</code>, <code>a[mid]</code>, <code>a[hi]</code>. Cheap (3 comparisons), usually much closer to the true median than any single element. This is what most real-world implementations use.</li>
<li><b>Middle element</b> <code>a[(lo+hi)/2]</code> — simple; avoids the O(n²) worst case on already-sorted input (the classic trap when using the first or last element).</li>
</ol>
<b>Why does pivot choice matter so much?</b>
<ul>
<li>A pivot near the median splits the array roughly in half → recursion depth ≈ <b>log n</b> → <b>O(n log n)</b> total work.</li>
<li>A pivot at the extreme (always min or max) splits into sizes 0 and n−1 → recursion depth ≈ <b>n</b> → <b>O(n²)</b> total.</li>
<li>So the pivot choice is exactly what separates the <i>average</i> case from the <i>worst</i> case in quicksort.</li>
</ul>"	Info2::Sorting
"<b>Heap Sort</b> — Explain what a <i>heap</i> is, how heap sort works (steps, ~5 bullets), code <code>heapify</code> and <code>heap_sort</code> in C, and state time &amp; space complexity (best / avg / worst, space)."	"<b>What is a heap?</b><br>
A <b>heap</b> is a <i>complete binary tree</i> (filled level-by-level, left-to-right) stored implicitly in an array. In a <b>max-heap</b>, every parent ≥ both its children (min-heap: parent ≤ children). For an element at index <code>i</code> (0-indexed):
<ul>
<li>Parent: <code>(i − 1) / 2</code></li>
<li>Left child: <code>2·i + 1</code></li>
<li>Right child: <code>2·i + 2</code></li>
</ul>
<b>Heap sort — steps:</b>
<ol>
<li><b>Build max-heap:</b> call <code>heapify</code> on every non-leaf node from index <code>n/2 − 1</code> down to <code>0</code>. Costs O(n).</li>
<li>The maximum element is now at index 0 (the root).</li>
<li>Swap <code>a[0]</code> with <code>a[i]</code> (the last element of the active heap) → max is placed in its final position.</li>
<li>Shrink the heap by 1 and call <code>heapify(a, i, 0)</code> to restore the max-heap property.</li>
<li>Repeat until the heap has 1 element. The array is now sorted ascending.</li>
</ol>
<b>C code:</b>
<pre><code>// Restore the max-heap property at node i,
// assuming the subtrees rooted at 2i+1 and 2i+2 are already valid heaps.
// n = size of the currently active heap.
void heapify(int a[], int n, int i) {
    // largest = index of the largest of {i, left child, right child}
    int largest = i;
    int l = 2*i + 1;   // left child
    int r = 2*i + 2;   // right child
    // compare with left child (only if it exists, i.e. l &lt; n)
    if (l &lt; n &amp;&amp; a[l] &gt; a[largest]) largest = l;
    // compare with right child (only if it exists)
    if (r &lt; n &amp;&amp; a[r] &gt; a[largest]) largest = r;
    // if a child was larger, swap and recurse down into that child
    if (largest != i) {
        int tmp = a[i]; a[i] = a[largest]; a[largest] = tmp;
        heapify(a, n, largest);
    }
}

void heap_sort(int a[], int n) {
    // ----- BUILD MAX-HEAP -----
    // Leaves (indices n/2 .. n-1) are trivially valid heaps on their own,
    // so we only need to heapify INTERNAL nodes.
    // We go bottom-up (last internal node → root) so that when heapify runs,
    // the children of i are already valid heaps. This is what makes
    // build-heap cost O(n) instead of O(n log n).
    for (int i = n/2 - 1; i &gt;= 0; i--) {
        heapify(a, n, i);
    }
    // ----- SORT -----
    // Repeatedly move the current max (root) to the end,
    // then restore the heap on the shrunken range [0, i).
    for (int i = n - 1; i &gt; 0; i--) {
        // move max (root) to position i (its final spot)
        int tmp = a[0]; a[0] = a[i]; a[i] = tmp;
        // active heap is now of size i; restore property at root
        heapify(a, i, 0);
    }
}</code></pre>
<b>Complexity:</b>
<ul>
<li>Time — Best / Average / Worst: <b>O(n log n)</b>. Build-heap is O(n), then n − 1 extractions cost O(log n) each.</li>
<li>Space: <b>O(1)</b> in-place (iterative <code>heapify</code>) or O(log n) recursion stack as written above.</li>
</ul>"	Info2::Sorting
"<b>Merge Sort</b> — Explain the <i>divide-and-conquer</i> principle (3 phases) and how merge sort applies it (steps, ~4 bullets), code it in C, and state time &amp; space complexity (best / avg / worst, space)."	"<b>Divide &amp; Conquer (3 phases):</b>
<ol>
<li><b>Divide</b> the problem into smaller sub-problems of the same type.</li>
<li><b>Conquer</b> each sub-problem recursively (base case: trivial size).</li>
<li><b>Combine</b> the sub-solutions into a solution of the original problem.</li>
</ol>
<b>Merge sort — steps:</b>
<ol>
<li>Base case: a sub-array of length ≤ 1 is already sorted → return.</li>
<li><b>Divide:</b> split the array at the middle index into two halves.</li>
<li><b>Conquer:</b> recursively merge-sort both halves.</li>
<li><b>Combine (merge):</b> walk two pointers through the two sorted halves and write the smaller current element into the output → produces one sorted array.</li>
</ol>
<b>C code:</b>
<pre><code>// Merge two already-sorted halves a[lo..mid] and a[mid+1..hi]
// into one sorted run stored back in a[lo..hi].
void merge(int a[], int lo, int mid, int hi) {
    // n1 = size of left half, n2 = size of right half
    int n1 = mid - lo + 1;
    int n2 = hi - mid;

    // create two temporary arrays and copy the two halves into them
    // (we need copies because we will overwrite a[lo..hi] while merging)
    int L[n1], R[n2];
    for (int i = 0; i &lt; n1; i++) L[i] = a[lo + i];
    for (int j = 0; j &lt; n2; j++) R[j] = a[mid + 1 + j];

    // i = read cursor in L, j = read cursor in R, k = write cursor in a
    int i = 0, j = 0, k = lo;

    // walk through BOTH halves at the same time
    while (i &lt; n1 &amp;&amp; j &lt; n2) {
        // pick whichever current element is smaller and copy it to a[k]
        if (L[i] &lt;= R[j]) a[k++] = L[i++];
        else              a[k++] = R[j++];
    }
    // at this point ONE of the two halves is fully consumed;
    // copy the leftover elements of the OTHER half (they are already sorted)
    while (i &lt; n1) a[k++] = L[i++];
    while (j &lt; n2) a[k++] = R[j++];
}

void merge_sort(int a[], int lo, int hi) {
    // base case: 0 or 1 elements → already sorted, nothing to do
    if (lo &lt; hi) {
        // DIVIDE: compute midpoint
        // (the form lo + (hi-lo)/2 avoids integer overflow vs. (lo+hi)/2)
        int mid = lo + (hi - lo) / 2;

        // CONQUER: recursively sort each half
        merge_sort(a, lo, mid);        // left half:  a[lo..mid]
        merge_sort(a, mid + 1, hi);    // right half: a[mid+1..hi]

        // COMBINE: merge the two sorted halves back together
        merge(a, lo, mid, hi);
    }
}</code></pre>
<b>Complexity:</b>
<ul>
<li>Time — Best / Average / Worst: <b>O(n log n)</b> (recurrence T(n) = 2·T(n/2) + Θ(n)).</li>
<li>Space: <b>O(n)</b> extra for the merge buffers + O(log n) recursion stack. <b>Not</b> in-place.</li>
</ul>"	Info2::Sorting
"<b>Dual-Pivot Quicksort</b> — In a dual-pivot quicksort implementation, an array <code>A[low...high]</code> is sorted based on two pivots <code>p1 = A[low]</code> and <code>p2 = A[high]</code>. The pivot <code>p1</code> must be less than <code>p2</code>, otherwise they have to be swapped. Here <code>low</code> is the left end of the array <code>A</code> and <code>high</code> is the right end of the array <code>A</code>.<br><br>
The partitioning process is the core of the dual-pivot quicksort. We begin partitioning the array into three proper partitions I, II and III, where:
<ul>
<li>Partition I: all elements are less than the left pivot <code>p1</code>.</li>
<li>Partition II: all elements are greater or equal to <code>p1</code> and less than the right pivot <code>p2</code>.</li>
<li>Partition III: all elements are greater than or equal to the right pivot <code>p2</code>.</li>
</ul>
After partitioning, the two pivots are placed in their proper final positions and the process is repeated recursively on each of the three partitions.<br><br>
Create a C program that implements dual-pivot quicksort to sort an array <code>A</code> of integers in increasing order. Your program should also print the array before and after sorting. For example, if the array is <code>[10, 7, 3, 15, 6, 2, 5, 1, 17, 8]</code>, the output should contain:
<pre><code>Before: [ 10 7 3 15 6 2 5 1 17 8 ]
After:  [ 1 2 3 5 6 7 8 10 15 17 ]</code></pre>"	"<b>Quick explanation in words:</b>
<ul>
<li>Choose two pivots: the leftmost and the rightmost element.</li>
<li>If they are in the wrong order, swap them so <code>p1 &lt;= p2</code>.</li>
<li>Then scan the array once and split it into three regions: smaller than <code>p1</code>, between the pivots, and greater or equal to <code>p2</code>.</li>
<li>Finally, put both pivots into their final places and recursively sort the three remaining parts.</li>
</ul>
<b>C code:</b>
<pre><code>#include &lt;stdio.h&gt;

#define ARRAY_SIZE 10

void swap(int A[], int i, int j) {
    // swap the two elements at indices i and j
    int tmp = A[i];
    A[i] = A[j];
    A[j] = tmp;
}

void printArray(int a[], int size) {
    // print the array in the required format: [ 1 2 3 ]
    printf("[");
    for (int i = 0; i &lt; size; i++) {
        printf(" %d", a[i]);
    }
    printf(" ]\\n");
}

void partitioning(int A[], int low, int high, int *p1, int *p2) {
    // A[low] is the left pivot, A[high] is the right pivot
    // l = first free position in partition I  (< p1)
    // k = current scanning index
    // g = first position of partition III (>= p2) from the right
    int l = low + 1;
    int k = low + 1;
    int g = high;

    // scan the array once and move each element into its correct partition
    while (k &lt; g) {
        // belongs to partition I: move it to the left side
        if (A[k] &lt; A[low]) {
            swap(A, l, k);
            l++;
            k++;
        }
        // belongs to partition III: move it to the right side
        else if (A[k] &gt;= A[high]) {
            g--;
            swap(A, k, g);
            // do NOT increment k here:
            // the element swapped in from the right has not been inspected yet
        }
        // otherwise it belongs to partition II and stays in the middle
        else {
            k++;
        }

        // prints intermediate partitioning steps
        printArray(A, ARRAY_SIZE);
    }

    // place the pivots into their final positions
    swap(A, low, l - 1);
    swap(A, high, k);

    // return the pivot positions through pointers
    *p1 = l - 1;
    *p2 = k;
}

void quicksort(int A[], int low, int high) {
    // base case: empty part or single element => already sorted
    if (high - low &lt;= 0) {
        return;
    }

    // ensure the left pivot is not larger than the right pivot
    if (A[low] &gt; A[high]) {
        swap(A, low, high);
    }

    int p1, p2;

    // partition the current subarray around the two pivots
    partitioning(A, low, high, &p1, &p2);

    // recursively sort the three partitions
    quicksort(A, low, p1 - 1);
    quicksort(A, p1 + 1, p2 - 1);
    quicksort(A, p2 + 1, high);
}

int main() {
    int A[] = {10, 7, 3, 15, 6, 2, 5, 1, 17, 8};
    int n = 10;

    printf("Before: ");
    printArray(A, n);

    quicksort(A, 0, n - 1);

    printf("After:  ");
    printArray(A, n);

    return 0;
}</code></pre>"	Info2::Sorting
"<b>Time complexity</b> — Rank the 8 most common time complexity classes from smallest (fastest) to largest (slowest)."	"<b>Ranking (smallest → largest):</b>
<pre><code>O(1) &lt; O(log n) &lt; O(n) &lt; O(n log n) &lt; O(n²) &lt; O(n³) &lt; O(2ⁿ) &lt; O(n!)</code></pre>
<b>What each one is:</b>
<ul>
<li><b>O(1)</b> — constant: same time regardless of n (array access, hash lookup).</li>
<li><b>O(log n)</b> — logarithmic: each step halves the problem (binary search).</li>
<li><b>O(n)</b> — linear: one pass through the input.</li>
<li><b>O(n log n)</b> — linearithmic: good comparison sorts (merge / heap / quick sort).</li>
<li><b>O(n²)</b> — quadratic: two nested loops (bubble / selection / insertion sort).</li>
<li><b>O(n³)</b> — cubic: e.g. naive matrix multiplication, Floyd–Warshall.</li>
<li><b>O(2ⁿ)</b> — exponential: subsets, naive recursive Fibonacci, brute-force SAT.</li>
<li><b>O(n!)</b> — factorial: all permutations, brute-force TSP.</li>
</ul>
<b>Rule of thumb:</b> any polynomial n^k grows slower than any exponential cⁿ, which grows slower than n!"	Info2::Complexity_and_Correctness
"<b>Time complexity</b> — What does <i>log n</i> mean in words when analyzing an algorithm? Why does it appear?"	"<b>In words:</b><br>
<code>log n</code> = the number of times you can <b>halve</b> n (or divide it by any constant factor &gt; 1) before reaching 1.
<ul>
<li>log₂ 1 024 = 10</li>
<li>log₂ 1 000 000 ≈ 20</li>
<li>log₂ 1 000 000 000 ≈ 30</li>
</ul>
Extremely slow growth!
<br>
<b>When it appears:</b><br>
An algorithm's complexity contains a <code>log n</code> factor whenever each step shrinks the problem to a <b>constant fraction</b> of its previous size — e.g. binary search halves the search range, balanced BST operations cut the depth in half, mergesort recurses on halves.
<br><br>
<b>Why no base?</b><br>
Changing the base of a log only multiplies by a constant (log₂ n = log₁₀ n / log₁₀ 2). Constants are dropped in O-notation → <code>O(log n)</code> is base-independent."	Info2::Complexity_and_Correctness

<li>Ω  ↔  ≥   (lower bound)</li>

"<b>Recurrences</b> — The maximum-subarray algorithm finds the contiguous subarray that has the largest sum within an unsorted array <code>A</code> with <code>n</code> integers. For example, for array <code>A = [-2, -5, 6, -2, -3, 1, 5]</code>, the maximum subarray is <code>[6, -2, -3, 1, 5]</code>.<br><br>
The algorithm works as follows:<br>
Firstly, it divides the input array into two equal partitions: I (<code>A[0]...A[mid]</code>) and II (<code>A[mid+1]...A[n-1]</code>). Afterwards, it calls itself recursively on both partitions to find the maximum subarray of each partition. The combination step decides the maximum-subarray by comparing three arrays: the maximum-subarray from the left part, the maximum-subarray from the right part, and the maximum-subarray that overlaps the middle. The maximum-subarray that overlaps the middle is determined by considering all elements to the left and all elements to the right of the middle.<br><br>
2.2 Provide C code for the maximum-subarray algorithm.<br>
2.3 What is the recurrence relation of the algorithm and its asymptotic tight bound?"	"<b>Idea in simple words:</b>
<ul>
<li>Split the array into a left half and a right half.</li>
<li>Recursively compute the best subarray fully inside the left half.</li>
<li>Recursively compute the best subarray fully inside the right half.</li>
<li>Also compute the best subarray that <b>crosses the middle</b>: it must end at <code>mid</code> on the left side and start at <code>mid+1</code> on the right side.</li>
<li>The overall answer is the best of those three candidates.</li>
</ul>
<b>C code:</b>
<pre><code>int maxOverlapArraySum(int arr[], int l, int m, int r) {
    // sum = running sum while we scan away from the middle
    // left_sum / right_sum = best sums found on each side
    int sum = 0;
    int left_sum = -50000;   // acts like -infinity

    // start at the middle and extend to the LEFT
    // this finds the best subarray that ENDS at index m
    for (int i = m; i >= l; i--) {
        sum = sum + arr[i];
        if (sum > left_sum) {
            left_sum = sum;
        }
    }

    // reset sum before scanning the right side
    sum = 0;
    int right_sum = -50000;  // acts like -infinity

    // start just right of the middle and extend to the RIGHT
    // this finds the best subarray that STARTS at index m+1
    for (int i = m + 1; i <= r; i++) {
        sum = sum + arr[i];
        if (sum > right_sum) {
            right_sum = sum;
        }
    }

    // the best crossing subarray must use both the best left part
    // and the best right part
    return left_sum + right_sum;
}

int maxSubArraySum(int arr[], int l, int r) {
    // base case: with one element, the best subarray is the element itself
    if (l == r) {
        return arr[l];
    }

    // split current interval into two halves
    int m = (l + r) / 2;

    // recursively solve left half, right half, and crossing case
    int leftArraySum = maxSubArraySum(arr, l, m);
    int rightArraySum = maxSubArraySum(arr, m + 1, r);
    int overlapArraySum = maxOverlapArraySum(arr, l, m, r);

    // return the largest of the three candidates
    if (leftArraySum >= rightArraySum && leftArraySum >= overlapArraySum) {
        return leftArraySum;
    } else if (rightArraySum >= leftArraySum && rightArraySum >= overlapArraySum) {
        return rightArraySum;
    }
    return overlapArraySum;
}

// initial call:
// int max_sum = maxSubArraySum(arr, 0, n - 1);</code></pre>
<b>Recurrence:</b>
<pre><code>T(1) = Θ(1)
T(n) = 2T(n/2) + Θ(n)</code></pre>
<b>Why this recurrence?</b>
<ul>
<li><code>2T(n/2)</code> because the algorithm recursively solves the left half and the right half.</li>
<li><code>+ Θ(n)</code> because the crossing subarray is computed by one scan to the left and one scan to the right of the middle, together linear in the current subproblem size.</li>
</ul>
<b>Step-by-step derivation of the bound:</b>
<pre><code>T(n) = 2T(n/2) + c n</code></pre>
Use the Master Method:
<pre><code>a = 2,  b = 2
n^(log_b a) = n^(log₂ 2) = n</code></pre>
Also
<pre><code>f(n) = c n = Θ(n)</code></pre>
So
<pre><code>f(n) = Θ(n^(log_b a))</code></pre>
This is <b>Master Method Case 2</b> with <code>k = 0</code>, hence
<pre><code>T(n) = Θ(n log n)</code></pre>
<b>Final answer:</b>
<pre><code>Recurrence: T(n) = 2T(n/2) + Θ(n)
Asymptotic tight bound: Θ(n log n)</code></pre>"	Info2::Recurrences

    return NULL;
}

void push(Node **top, int x) {
    Node *new_node = malloc(sizeof(Node));

    // new node becomes the new top
    new_node-&gt;value = x;
    new_node-&gt;next = *top;
    *top = new_node;
}

int pop(Node **top) {
    // caller should ensure the stack is not empty
    Node *tmp = *top;
    int x = tmp-&gt;value;

    // remove the top node
    *top = tmp-&gt;next;
    free(tmp);

    return x;
}</code></pre>

"<b>Queue</b> — What is the queue principle? What happens at the head and the tail? Explain circular indexing."	"<b>Principle:</b> <b>FIFO</b> = <b>F</b>irst <b>I</b>n, <b>F</b>irst <b>O</b>ut.<br>
The oldest inserted element is removed first.
<br><br>
<b>Head vs. tail:</b>
<ul>
<li><b>enqueue</b> inserts at the <b>tail</b></li>
<li><b>dequeue</b> removes from the <b>head</b></li>
</ul>
<b>Circular indexing:</b><br>
In an array-based queue, after reaching the last array position you do not stop. You wrap around to index <code>0</code>.
<pre><code>next_index = (current_index + 1) % capacity</code></pre>
This makes the array behave like a circle.
<br><br>
Example with capacity 5:
<pre><code>0 1 2 3 4
        ^ tail

tail = (4 + 1) % 5 = 0</code></pre>
So after index 4, the next free position is again index 0.
<br><br>
<b>Why useful?</b><br>
It avoids shifting all elements after each dequeue. Head and tail simply move around the ring."	Info2::Abstract_Data_Types
"<b>Queue</b> — What is the structure of a queue in C? Write <code>enqueue</code> and <code>dequeue</code> in C."	"<pre><code>#define CAPACITY 100

typedef struct {
    int a[CAPACITY];
    int head;   // index of the first element
    int tail;   // index where the next inserted element goes
    int size;   // current number of stored elements
} Queue;

void initQueue(Queue *q) {
    q-&gt;head = 0;
    q-&gt;tail = 0;
    q-&gt;size = 0;
}

void enqueue(Queue *q, int x) {
    // assume the queue is not full
    q-&gt;a[q-&gt;tail] = x;                  // insert at tail
    q-&gt;tail = (q-&gt;tail + 1) % CAPACITY; // move tail circularly
    q-&gt;size++;
}

int dequeue(Queue *q) {
    // assume the queue is not empty
    int x = q-&gt;a[q-&gt;head];              // remove from head
    q-&gt;head = (q-&gt;head + 1) % CAPACITY; // move head circularly
    q-&gt;size--;
    return x;
}</code></pre>
<b>Why store <code>size</code>?</b><br>
It makes checking empty/full easier:
<ul>
<li>empty iff <code>size == 0</code></li>
<li>full iff <code>size == CAPACITY</code></li>
</ul>"	Info2::Abstract_Data_Types

"<b>Ordered List</b> — How do you insert a value iteratively into an ordered list?"	"<pre><code>#include &lt;stdlib.h&gt;

struct node {
    int value;
    struct node *next;
};

void insert_ordered(struct node **L, int x) {
    struct node *new_node = malloc(sizeof(struct node));
    new_node-&gt;value = x;
    new_node-&gt;next = NULL;

    // special case: empty list or x belongs before the first element
    if (*L == NULL || x &lt; (*L)-&gt;value) {
        new_node-&gt;next = *L;
        *L = new_node;
        return;
    }

    // walk until cur points to the node after which x should be inserted
    struct node *cur = *L;
    while (cur-&gt;next != NULL &amp;&amp; cur-&gt;next-&gt;value &lt; x) {
        cur = cur-&gt;next;
    }

    // insert new_node between cur and cur->next
    new_node-&gt;next = cur-&gt;next;
    cur-&gt;next = new_node;
}</code></pre>
<b>Idea:</b> move forward until you find the first place where the next value is not smaller than <code>x</code>, then splice the new node into that gap.<br>
<b>Complexity:</b> <code>O(n)</code>."	Info2::Abstract_Data_Types
